**1. Preferred minimal split**

**Proposal — compiler responsibilities:**

- Parse one closed client/scope/endpoint tree.
- Resolve owner-qualified references, placements, representation types, and generated-name collisions.
- Resolve path/subdomain inheritance and query/header structural operations for each endpoint.
- Generate ordinary Rust clients, scope snapshots, endpoint builders, and construction code.
- Leave Rust payload types opaque. Rust trait checking determines encoding capability.

The important simplification is to initially support **introduction, append, unconditional replace, and remove**. Their surviving contributions can be determined during macro expansion. Optionality then controls whether a surviving source emits anything; it does not require a runtime patch interpreter.

**Proposal — runtime responsibilities:**

- Scalar formatting followed by placement-specific encoding and validation.
- Native URL/header/body construction.
- A consuming prepared-request wrapper carrying the reqwest client, request, and typed decoder.
- JSON/Text/Bytes/Empty representations.
- Structural errors and sensitivity-aware formatting.

Use two packages: a runtime/facade and a proc-macro package. Keep the compiler’s resolved model private. No public operation model, owner-projection framework, transport trait, or serialized contract IR is necessary.

Snapshots can use private `Arc<T>` slots and retained initializer slots. This avoids requiring arbitrary payloads to implement `Clone`. Concord never mutates captured payloads; user-provided interior mutability and nondeterministic encoders remain outside the determinism guarantee.

These short examples show **proposed V4 calls**, not APIs implemented or compile-verified in this checkout. Assume a generated `Catalog` with required root `tenant`, scope `regional(region)`, and endpoint `item(id)` returning JSON:

```rust
let api = Catalog::builder(http.clone())
    .set_tenant("acme")
    .build()?;

let item = api.regional("eu")
    .item("a/b")
    .set_locale("fr")
    .send().await?;
```

Native handoff retains the selected decoder without a transport abstraction:

```rust
let prepared = api.regional("eu").item("42").prepare()?;
let (http, mut request, decoder) = prepared.into_parts();

request.headers_mut().insert("x-trace", "demo".parse()?);
let response = http.execute(request).await?;
let item = decoder.decode(response).await?;
```

`.prepare()` performs no network I/O. `.send()` consumes the endpoint builder, prepares once, calls `Client::execute` once, then decodes. I would omit direct `.await` support: an explicit verb makes execution easier to recognize.

**Tradeoff:** endpoint specialization duplicates some generated code. Shared runtime functions should own byte manipulation; generated code should chiefly select and connect typed values.

**2. A genuinely different viable alternative**

**Alternative — typed values plus an interpreted request recipe.** Generate typed owner snapshots and static operation tables. At preparation, a small generic evaluator walks the owner chain, selects surviving lazy emissions, then encodes them. This resembles V3’s head-program mechanism, stripped of execution policy.

It can support conditional replacement naturally: absent child input preserves the ancestor; present input replaces it. Defaults and typed payloads still belong to generated snapshots, while composition belongs to runtime data.

| Candidate | Strong reason to choose it | Failure condition |
|---|---|---|
| Preferred: endpoint specialization | Small runtime; suppressed encoders disappear from the endpoint’s construction path; simple preparation | Real contracts repeatedly need conditional inheritance, or expansion/compile cost becomes unacceptable at realistic scale |
| Alternative: interpreted recipes | Shared composition machinery; conditional fallback; less repeated generated composition code | Runtime evaluation becomes a second extensible language, requires pervasive erasure/allocations, or produces worse diagnostics than generated Rust |

**Hypothesis:** specialization wins for the intended closed, static domain tree. That needs measurement, not an assumed performance advantage.

The alternative remains within scope only if its recipe machinery stays private. It does not justify runtime-authored endpoints or an execution-hook system.

**3. Recommended semantics**

**Values and defaults**

| Declaration | Initial selection | Controls |
|---|---|---|
| `x: T` | Required caller payload | `set_x(T)`; no omission or reset |
| `x?: T` | Outer absent | `set_x(T)`, `omit_x()` |
| `x: T = expr` | Retained initialized payload | `set_x(T)`, `reset_x()` |
| `x?: T = expr` | Outer present containing retained payload | `set_x(T)`, `omit_x()`, `reset_x()` |
| `x: Option<T>` | Required payload, including valid `None` | Same as required `T` |
| `x?: Option<T>` | Outer absent, present `None`, or present `Some(T)` | `set_x(None)` selects present-inner-None; `omit_x()` selects outer absence |

Missing required root inputs should produce **one structured error listing all missing fields**. Required scope/endpoint inputs should be constructor arguments. This avoids a typestate type parameter for every root requirement while keeping nested navigation direct.

An empty string is supplied input, not missing input. Its placement may still reject it—for example, an empty DNS label.

Evaluate defaults in declaration order:

- Root: when its builder is created.
- Scope: when that scope is selected.
- Endpoint: when its builder is constructed.

Overrides do not avoid that initial evaluation. Clone, preparation, sending, and reset do not repeat it. Reselecting a scope or constructing another endpoint creates a new owner boundary and evaluates its local defaults again.

`#[default]` means exactly `<T as Default>::default()`. Thus `#[default] x?: Option<U>` starts **present with payload `None`**.

Allow initializer expressions in their authored Rust lexical context, without DSL-value dependency resolution. They are ordinary synchronous Rust expressions; Concord should neither schedule them nor catch their panics.

I would initially omit generated `replace_x` and `set_x_if_some` methods. Exact outer replacement is expressible using `set_x`/`omit_x`; conditional updates use ordinary Rust. Retain V3’s small identity/string conversion set rather than blanket `Into`, recursive optional conversions, or `Display` coercions.

**Wire meaning of `Option<T>`**

No automatic scalar encoding for `Option<T>`. Require an explicit adapter when it appears in a path/query/header placement.

For example, an explicitly selected JSON scalar adapter could produce:

- Outer absent: no query occurrence.
- Present `String::new()`: `k=`.
- Present payload `Option::None`: `k=null`.
- Present payload `Some("")`: `k=%22%22`.

A present empty `each` sequence emits zero occurrences. Its selected state differs from absence even when the resulting wire request is identical.

**Ownership**

Bare names bind only the current owner. Ancestors require `client.tenant` or `regional.region`. Never search outward for a matching bare name. Scope names must be unique along an ancestor chain so qualification remains unambiguous.

Consuming setters create a new selection. Requests already constructed retain their captured owner selection. Updating a child does not update its parent or siblings.

**Query/header composition**

Use root → scopes → endpoint order. Within an owner, define a fixed ordering: direct placements in declaration order, then explicit block statements in source order.

| Operation | Meaning |
|---|---|
| Introduction | Compile error if an earlier potential writer exists, even if optional |
| Append | Retain earlier occurrences; add present source occurrences at this position |
| Replace | Delete all earlier occurrences; emit the replacement if present |
| Remove | Delete all earlier occurrences |
| Omit a source | Suppress its emissions; it does not cancel an authored replacement |

Require replace/remove to name an earlier potential writer, catching misspellings. Replacement occupies its authored position rather than the original occurrence’s position.

For example:

`a=1, k=root, z=9` → append `k=scope` → replace `k` with absent optional → append `k=end`

produces **`a=1&z=9&k=end`**.

Query keys are case-sensitive; headers use case-insensitive identity. Headers use native `HeaderMap` values, with explicit append and no automatic comma joining. Reject repeated known singleton fields; ordinary `Authorization` and `Cookie` inputs are allowed as scalar headers.

Only surviving contributions are encoded. A removed expensive, invalid, or sensitive contribution must not run its encoder. This guarantee concerns **encoding**, not initializer evaluation.

**URL semantics**

- Treat the base path as a prefix when appending; do not use file-relative `Url::join` behavior.
- Preserve the base path when no generated path is added.
- Join component boundaries with one slash; permit an explicitly requested final trailing slash.
- Reject leading-slash templates, internal `//`, and literal `.`/`..` segments.
- Dynamic path values are one segment: `a/b` → `a%2Fb`; `%2F` → `%252F`. Reject empty, dot-only, and backslash-containing dynamic segments.
- Reject base userinfo, query, and fragment initially; require explicit query declarations.
- Subdomain lists prepend to inherited generated labels; replacement drops generated labels while retaining the base suffix and port.
- Apply the same DNS policy to static and dynamic labels: ASCII labels, normalize uppercase to lowercase, reject embedded dots and Unicode. Callers can explicitly supply validated punycode.

**Bodies and responses**

Start with explicit representation selection, without examining Rust type names:

- No body, zero-length byte body, and JSON `null` remain distinct.
- JSON supplies `Content-Type` only when no authored value exists; explicit vendor media types are permitted. Accept behaves similarly.
- Removal affects Concord-authored contributions, not subsequent codec defaults or reqwest client defaults.
- Typed send accepts 2xx, then invokes the selected decoder.
- JSON on 204 fails decoding; Empty accepts zero decoded bytes and rejects nonempty bodies.
- `Option<T>` output never implies 404-to-None.
- For minimum machinery, JSON decoding ignores Content-Type; Text uses strict UTF-8; Bytes preserves bytes. Applications needing media enforcement or streaming use the native response path.

**Sensitive metadata**

Sensitivity follows sources into placements and is **sticky per destination key along the selected chain**, including replaced or removed contributions. Header identity is normalized; query identity stays exact.

Use a small documented sensitive-name safety net, plus explicit marks. Redact an entire composed path segment when any constituent is sensitive; withhold the host when a sensitive label participates.

Generated Debug should default to structural output. More detailed Concord formatting must use metadata, never native request Debug. Set native header sensitivity flags as a courtesy, but promise protection only for Concord-produced output.

Errors should distinguish preparation, transport, status, and decoding without automatically retaining printable URLs, body excerpts, serializer messages, or arbitrary source chains. Raw native execution remains available when applications need native diagnostics.

**4. Two realistic reqwest interoperability paths**

1. **Native request ownership:** accept an application-configured `reqwest::Client`; export `(Client, Request, Decoder)`. Applications inspect or mutate the request, execute it, and optionally use the decoder afterward. Export consumes the safe wrapper, avoiding stale redaction metadata after arbitrary mutation.

2. **Native RequestBuilder bridge:** use reqwest’s existing `RequestBuilder::from_parts(client, request)`. Applications can add native timeout/body/multipart settings and obtain a raw response. No forwarding copy of reqwest’s configuration surface is needed.

These are supported by the locally installed reqwest 0.13.4 APIs: [request.rs:189](/home/canarit/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/reqwest-0.13.4/src/async_impl/request.rs:189), [request.rs:492](/home/canarit/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/reqwest-0.13.4/src/async_impl/request.rs:492).

A critical boundary: **one Concord execute call does not mean one physical HTTP exchange**. Native redirects and native recovery remain application-configured behavior. M05 needs that interpretation to coexist with M02’s interoperability requirement.

**7. Severity-ranked things not to build**

- **P0 — violates the product:** credential acquisition/refresh, limiter admission, retries, pagination controllers, or hooks specifically intended to host them. Feature flags and “extras” do not resolve the scope violation.
- **P0 — undermines interoperability:** a managed executor, replacement HTTP client, or parallel reqwest configuration builder.
- **P1 — recreates the removed architecture:** operation identities, dispatch journals, attempt budgets, policy clocks, completion observers, and a universal request-control matrix.
- **P1 — makes native access unnecessarily difficult:** replay factories, stream leases, custom response drivers, or transport-private request/response wrappers.
- **P1 — creates a second framework:** public runtime endpoint programs, middleware registration, or extensible execution callbacks.
- **P2 — increases compiler cost before proving value:** full schema export/diff tooling, default dependency graphs, validation languages, or typestate for every optional/defaulted control.
- **P2 — weakens predictability:** type-name inference, silent key overwrites, implicit conditional fallback, and automatic status-to-Option conversion.
- **P2 — overstates security:** claims that sensitivity metadata protects external reqwest Debug, middleware, tracing, or application logs.
