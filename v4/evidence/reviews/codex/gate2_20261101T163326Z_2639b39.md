**Architecture and choices worth retaining.** V4 is substantially a thin domain layer over reqwest. `Prepared::send` performs preparation, one `Client::execute`, status checking and decoding. I found no Concord transport builder, middleware executor, retry loop or execution-policy framework. The supplied client is cloned and executed; locally cached reqwest source confirms that client defaults are applied during execution. Concord’s base override is domain composition, consistent with D2/D5.

The request/response escape hatches are sensibly designed: immutable inspection, consuming `into_parts`, native `RequestBuilder::from_parts`, reusable declared decoding, and `send_raw`. The one-way native handoff avoids stale Concord redaction metadata.

Required/optional/defaulted storage follows explicit syntax rather than type-name inspection. Defaults are emitted at owner construction, and clone/setter/prepare paths do not reevaluate their initializer expressions. Copy-on-write owner snapshots are straightforward. These conclusions still need the counter and snapshot tests.

Body handling mostly follows D7 on inspection: explicit representations, conditional Content-Type insertion, JSON decoding independent of Content-Type, strict UTF-8 Text, preserved Binary bytes, unread non-2xx responses, and no automatic 404-to-`None`. The unit-buffering issue above is separate from the accepted lenient unit semantics.

**Opinion on D4.** I still find exact `replace` easier to predict from optional selection alone. However, the accepted D4 rule is coherent and defensible: absent `override` means fallback; `remove` followed by introduction gives exact replacement. The compiler implements that distinction through generated branches, without a runtime patch interpreter.

I would retain D4 for this iteration, conditional on discriminating tests. In particular, `None` must preserve inherited occurrences, while a present empty `each` collection must clear them. Nested optional overrides must select the latest present writer. This is a usability tradeoff, not an implementation defect merely because the blind proposal preferred another rule.

**Missing evidence and unresolved semantics.**

- The seven slice tests use real generated code and loopback HTTP, which is a good foundation. They contain no nested scope, query composition, declared header composition, body, sensitivity or negative compilation cases. M02 establishes default headers/user-agent only.

Concord’s top-level error formatting is deliberately restrained, and built-in JSON descriptions avoid quoting bodies. Transport errors have their URL removed.
