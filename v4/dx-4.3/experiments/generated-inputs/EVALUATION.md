Contract: [`../../DECISIONS.md`](../../DECISIONS.md), G1 (written before the code). Prototype:
branch `concord-v4.3-dx-generated-inputs`, commits `6f204ae` (generator) and `214980d` (caller

Both surfaces use the same runtime (`concord-core` unchanged), transport, decoders, SDK
declaration (`examples/sdk`) and fixture (`examples/fixture`). Only the macro differs.

## 1. What was built

The real macro emits, for every endpoint of every declaration in the workspace, an input record;
nothing is handwritten per endpoint. For `Catalog.tenant.listing.list` (from `examples/sdk`):

```rust
#[non_exhaustive]
pub struct CatalogTenantListingListInput {
    pub q: Option<String>,
    pub tags: Option<Vec<String>>,       // None: inherit the listing's default tags
    pub limit: u32,                      // starts as 20 (the declared initializer)
    pub region: Option<Option<String>>,  // None: inherit; Some(None): omit; Some(Some(r)): replace
    pub cursor: Option<String>,
}
impl CatalogTenantListingListInput { pub fn new() -> Self }
impl CatalogTenantListing { pub fn list_with(&self, input: CatalogTenantListingListInput) -> CatalogTenantListingList }
impl CatalogTenantListingList {
    pub fn input(&self) -> &CatalogTenantListingListInput;
    pub fn input_mut(&mut self) -> &mut CatalogTenantListingListInput;
    pub fn into_input(self) -> CatalogTenantListingListInput;
}
```

(The shape above is the generated one with docs elided; each field's generated documentation
states its starting state, what `None` means and, for an inherited key, the owner that declares
it, e.g. "declared by `Catalog.tenant.listing` (value `default_tags`)".)

Defects found and corrected during the evaluation (each re-verified):

1. A `#[deprecated]` endpoint: its navigation method first called the (equally deprecated)
   `_with`, so `#![deny(warnings)]` callers failed (`crates/concord/tests/attributes.rs`). Fixed:
   the navigation method builds the request directly.
2. Bound errors for a value type (missing `Display`/`ToHeaderValue`) were reported twice, once
   per generated `Debug`. Fixed: both `Debug` impls share one private helper, emitted after the
   request's impls, so the diagnostics and their order are byte-identical to V4.2's.

## 3. Matched caller tasks (DX01–DX03)

Same tasks, same SDK, same fixture; `tasks/tests/tasks.rs` requires identical results **and
identical wire requests** from both solutions (it passes).

**T1 — saved search, branched, edited, rebound (DX01).** Existing interface: the application must
keep its own mirror of the endpoint's inputs, including the knowledge that leaving `limit` alone
means "the SDK's 20":

```rust
#[derive(Clone, Debug, Default)]
pub struct SavedSearch {
    pub q: Option<String>,
    pub tags: Option<Vec<String>>,
    pub limit: Option<u32>,
}

impl SavedSearch {
    pub fn on(&self, listing: &CatalogTenantListing) -> CatalogTenantListingList {
        let mut request = listing
            .list()
            .maybe_q(self.q.clone())
            .maybe_tags(self.tags.clone());
        if let Some(limit) = self.limit {
            request = request.set_limit(limit);
        }
        request
    }
}
```

Input records: the generated record is that mirror.

```rust
let mut saved = CatalogTenantListingListInput::new();
saved.q = Some("e".into());
saved.limit = 3;
let mut everything = saved.clone();
everything.tags = Some(Vec::new());
// …
acme.list_with(saved.clone()).send().await?;
studio.list_with(saved.clone()).send().await?;
```

**T2 — clear inherited tags and region for one call, check before sending (DX02).** Equivalent
effort: `set_tags(Vec::new()).set_region(None)` versus two field assignments. The record lets the
caller read back the call's *own* values (`one.input().tags`); what the context adds (the tags it
inherits, the base, static headers) is outside the record in both cases and is seen only by
preparing. Where the inherited key comes from: the setter's documentation says "keeps the
inherited `tag` (`override ... else inherit` in `Catalog.tenant.listing.list`)"; the field's
documentation names the declaring owner and value (`Catalog.tenant.listing`, `default_tags`).
Server defaults (the region when none is sent) are unknown to both.

**T3 — requests handed over as values, read and re-run for another tenant.** Existing
interface: the `limit` can only be recovered by preparing a clone and parsing the URL text, and
the requests cannot be moved to another tenant — the code that built them must be called again.
Records: `request.input().limit` (a `u32`) and `other.list_with(request.into_input())`.

**DX03 — evolution.** Adding `query sort?: String` (v2) leaves the saved input-style consumer
compiling unchanged. Making the initialized `limit` optional (`limit?: u32 = 20`, v3), which a
setter caller does not notice, breaks the field user (`E0308`: `u32` versus `Option<u32>`). Struct
literals are rejected downstream by design (`E0639`). An SDK author therefore gains a new
compatibility rule: a value's presence kind (`?`, `= expr`) becomes part of the field type.

## 4. Editor observations (DX04) and cost (C05)

rust-analyzer 1.99.1 (the pinned toolchain's), probed over LSP on the saved consumers
(`ra_probe.py`, `evidence/g1-ra-probe.json`):

| Action | Input record | Setter (existing) |
|---|---|---|
| completion on the receiver | fields `limit`, `q`, `tags` (plus `Clone` items) | `set_*`, `maybe_*`, `prepare`, `send` (and, with the prototype, `input`, `input_mut`, `into_input`) |
| hover | field type and generated docs, including the declaring owner of an inherited key | method signature and generated docs |
| go to definition | the value's declaration line inside the SDK's `api!` block | `concord-macros/src/lib.rs` (the macro's entry point) |
| `list_with` / type name | the endpoint's declaration line | — |

Generated code and build time, same declarations, same toolchain:

| Measure | V4.2 macro | Prototype | Change |
|---|---|---|---|
| expanded `examples/sdk` (rustfmt lines) | 4,401 | 5,022 | +14% |
| expanded 480-endpoint synthetic SDK (lines) | 113,045 | 143,845 | +27% |
| same, bytes | 5,092,272 | 6,911,372 | +36% |
| compile of that test crate, no incremental, median of 5 (s) | 2.60 | 3.01 | +16% |

The cost is paid by every declaration, whether or not its callers use inputs. Runtime work of
`prepare` is unchanged in kind (the same code reads `self.__in.x` instead of `self.x`); no runtime
performance claim is made either way.
