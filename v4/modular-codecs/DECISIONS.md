# Modular codecs increment — decisions

IDs `MC*` belong to this increment. Earlier decisions (`v4/finalization/DECISIONS.md` F01–F13)
stay in force unless a row here says otherwise.

| ID | Decision | Why | Evidence |
|---|---|---|---|
| MC01 | Rust 1.99.1 is both `rust-version` (every production crate inherits it) and the `rust-toolchain.toml` pin; the separate 1.85 lanes are gone | Owner: latest verified stable; one release for minimum and development means the ordinary gate is the minimum check, and the old local/CI MSRV selections cannot drift apart again | `scripts/check-ci.py --toolchain`; state-2 control `686cd24` |
| MC02 | A format is an ordinary Rust type path (`format Json;`); no word is reserved and the macro has no codec table | Owner: Json and a downstream codec resolve the same way; a lowercase alias is ordinary Rust | `ui/format_unknown_type.rs`, `attributes.rs` (cfg-disabled formats are never resolved) |
| MC03 | Four crates: `concord-core` (runtime, contracts), `concord-extras` (standard formats, public traits only), `concord-macros` (unchanged role), `concord` (re-exports + `api!` bridge passing `$crate::__macro::concord_core`) | Owner's crate split; the bridge is one `macro_rules!` line, not a preprocessor | `scripts/check-graph.py`; four-crate `package-check.sh` |
| MC04 | `NativeKey` is sealed (private supertrait, `HeaderName` only) | Cached per-value decisions assume a key path's name cannot change | `ui/native_key_sealed.rs` (compiles on `dfdeed8`, rejected now), `ui/native_key_deref.rs` |
| MC05 | Riot's live client refuses redirects (`http_policy`, `live_http_client`); Concord itself has no redirect policy | reqwest's cross-origin strip list omits `X-Riot-Token` | `examples/riot/tests/redirects.rs` (control shows the default policy forwarding the key) |
| MC06 | `scripts/verify.sh` is the one gate inventory; CI calls it | Duplicated command lists had drifted | `scripts/check-ci.py --workflow` |
| MC07 | Each native key occurrence records its owner when its contribution is recorded | Replaces per-key scans of every owner; occurrences stay distinct | `emit::tests::key_occurrence_owner_matches_a_scan_of_every_owner` |
| MC08 | `Decode<T>`: `type Context: Send + 'static`; `const ACCEPT: Option<&'static str> = None`; `check_content_type(&ResponseHead)` (default accepts; the only step `IgnoreContentType` skips); `context(&ResponseHead) -> Context` (every other head check); `decode_body(Context, Bytes)` (never sees the head; also the named body-only route). Order on a 2xx: content type → context → read → decode. `Decoder<T>` stays `Copy`: a monomorphized head function returning a boxed `FnOnce(Bytes)` (no allocation for a zero-sized context) | Opus and Sol independently chose this (B) with executable evidence; A (head passed again after the read) lets a decoder reject on head data after the body is consumed, losing the unread response (Opus CE1) | frozen [`arch-opus-REPORT.md`](reports/arch-opus-REPORT.md) §2.2–2.3, CE1; [`arch-sol-REPORT.md`](reports/arch-sol-REPORT.md) §1–2 |
| MC09 | `Encode<T>` keeps `const CONTENT_TYPE` (compile-time checked); a per-body media type stays a native edit after `into_parts` | Sol's `EncodedBody` adds a runtime-checked path no current task needs; the static check and generated docs stay | — |
| MC10 | `CodecError::new(&'static str)` + `.at(&'static str, u64)` (3 inline positions: 4 made it 136 bytes, over clippy's large-error threshold; Sol's prototype also used 3) + `.with_source(..)`; `source_unredacted()`; `ErrorKind::Metadata` holds `(CodecError, Response)` unread; `Error::codec_error()`; `status()` stays `Status`-only, `response()`/`into_response()` cover `Status` and `Metadata` | Both challengers; static labels are a safer default, not a proof | — |
| MC11 | The decoder's `ACCEPT` is inserted after authored composition, only for a typed output, when no authored `accept` survives and the chain's last `accept` operation is not `remove`; checked at compile time like `CONTENT_TYPE`; marked sensitive when the endpoint classifies `accept` sensitive (as Concord's inserted `Content-Type` already is). It never enters `HeaderPlan`. A request header replaces a reqwest client default at execution; suppression leaves the client default | Both challengers' truth tables agree; locked reqwest 0.13.5 fills only vacant names | — |
| MC12 | `HeaderPlan::compose` splits into a presence-free structural pass (reserved, duplicate introduction, missing target, `content-type` vs declared media) shared with a generated `Client::validate_header_names() -> Result<(), HeaderNameErrors>`, and a liveness step that reads presence. The `content-type` rule's verdict is unchanged; the contribution it names becomes the last surviving one (Opus: 1,618 of 229,790 error runs) | Both challengers; exhaustive comparison shows verdicts were already presence-independent | — |
| MC13 | Facade features: `json` (default) and `form` imply `extras` (`Text`, `Binary`, `IgnoreContentType`); with `default-features = false` there is no standard format at all; `reqwest-defaults` forwards to core. Facade tests that use `Text`/`Binary` declare `required-features = ["extras"]` | A02: the facade without extras compiles a downstream codec with no extras in its graph | `scripts/check-graph.py` |
| MC14 | `validate_header_names()` is generated on every client (it returns `Ok` when no chain writes a native key) and reserved as a method name; one problem per endpoint (the one `prepare()`'s header composition reports; earlier build steps such as body encoding run first and may fail first), declaration order; it reads only literal statics and key accessors | H01–H06; a per-endpoint `static` of shapes shared with `prepare()` keeps the two from drifting | `validate_names.rs`, `header_plan.rs::the_validator_and_prepare_share_one_verdict` |
| MC15 | Strict `Json` refuses `application/json+xml` (`mime` reports subtype `json` with suffix `xml`) | Found by the media matrix; Sol's prototype hit the same trap | `crates/concord-extras/tests/media.rs` |
| MC16 | Typed hierarchical paths are deferred; `examples/compat` maintains a native recipe (`write_resource_segments`) | The bounded Terra prototype worked but a static-index mutant mis-redacted segments, so a generated surface needs a per-segment sensitivity design first; the native recipe covers the use today | [`path-terra-report.md`](reports/path-terra-report.md); REVIEW_TRIAGE R6 |
| MC17 | Extras read the parameters with a small hand-written RFC 9110 scanner (parameters only: a second, narrow parser next to `mime`, which still parses type and subtype, the text before the first `;`). `Json` and `Form` refuse a repeated `charset` as ambiguous; `Text` refuses a readable non-UTF-8 `charset`, repeated or not, and nothing else; a field is readable when it is one visible-ASCII value whose type and subtype are non-empty tokens (`mime` alone accepts `text/`) and whose parameters follow the grammar | Final audit X-F1 (`mime` 0.3.17 misreads a quoted value followed by another parameter) and X-F2 (only the first `charset` was read); semantic review M4 (`mime` refused whitespace before `;` and empty parameters, which RFC 9110 allows) | `crates/concord-extras/tests/media.rs`, `metadata.rs::charset_parameters_are_read_exactly` |
| MC18 | Names stay: `ErrorKind::Metadata`, `Decode::{check_content_type, context, decode_body}`, `CodecError`, `validate_header_names` | Chosen with both architecture challengers and both journey probes; the fresh-use trials completed their tasks with them (Sonnet would prefer others, Terra found them clear once read). Renaming late costs every doc and fixture for no behaviour | REVIEW_TRIAGE, fresh-use section |
| MC19 | `prepare()` keeps its build order (body encoding, host, path, query, then headers); `validate_header_names()`'s documentation is narrowed to what it proves: a reported endpoint can build no request, and its `prepare()` returns that problem unless an earlier step fails first | Semantic review S2. The trade-off, stated by the re-review: for an endpoint that can never be built, the error a request reports depends on its values, and an encoder runs (consuming a one-shot payload) before the certain failure; a value-free check first would make that error deterministic. Kept because such an endpoint is a declaration error that `validate_header_names()` reports without values, and moving the check is a code-generation change to `prepare()` late in this increment; a later increment may move it (SEMANTICS §6 would change one sentence). The side Opus re-review accepts the outcome and records its disagreement with the rationale | `validate_names.rs::earlier_build_steps_fail_first` |
| MC20 | The gate lints feature subsets (`clippy-features`: `concord-extras` with no, `json` and `form` features; the facade with `extras` only), not only the unified workspace | Two dead-code lints of the `extras`-only build went unseen through four review rounds; the measurement found them (REVIEW_TRIAGE P-1) | `scripts/verify.sh` |
