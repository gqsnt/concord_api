**(a) Docs only — strongest first candidate.** State query order explicitly, include fixed values and group/`query(..)` positions, annotate path holes with the escape set, and expose selected format header facts beside the endpoint. Label any example with its inputs and observation boundary.

Expected wire/API breakages: none. Concept cost: no new caller ceremony; some documentation volume. **A proc macro cannot generally recover arbitrary custom associated-constant values or `Display` output from declaration tokens.** Concrete FRED values therefore need format documentation/links or independently checked SDK examples; printing `Xml` alone does not solve that miss.

**What automation can decide**

Prefer a static documentation contract first:

- Independently assert generated **navigation and request-type** text contains fixed values/order, group positions, hole-encoding rules and format-header provenance.
- Use Kubernetes + MediaWiki for ordering, Nager for reserved characters, FRED for a custom format preference, and ClickHouse/OpenAI/B2 for typed-output/header boundaries.
- Check examples against independent expected targets/headers, not another rendering of the same generator model. Existing encoding assertions provide useful controls. [composition.rs:57](/home/canarit/projects/Concord_Desirability_Loop/work/wt/h16s/crates/concord/tests/composition.rs:57)
- Preserve composition behavior using the independent oracle, and header fallback using `accept.rs`; retain compiler fixtures for invalid format constants. [oracle_composition.rs:5](/home/canarit/projects/Concord_Desirability_Loop/work/wt/h16s/crates/concord/tests/oracle_composition.rs:5), [format_invalid_accept.stderr:1](/home/canarit/projects/Concord_Desirability_Loop/work/wt/h16s/crates/concord/tests/ui/format_invalid_accept.stderr:1)

**A static “generated docs state the actual composition” check can decide a bounded documentation-completeness card. It cannot alone decide that readers predict correctly.** Arbitrary `Display`, `QueryPairs`, runtime body media, replacement bases and policies also prevent a universal concrete-request claim from declaration tokens alone. I3 R1 remains a reader instrument for discoverability.
