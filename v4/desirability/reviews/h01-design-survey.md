**1. What callers see today**

The generator has three cases:

| Declaration | Generated signature / awaited result |
|---|---|
| No send policy | `pub async fn send(self) -> Result<T, concord::Error>` |
| `send Policy;` | `pub fn send(self) -> impl Future<Output = <Policy as SendWith<T>>::Output> + Send` |
| `send Policy -> Template;` | Same future form, with `Output = Template<T>` and an equality bound against the policy implementation |

With `operations Name;`, the projection uses `SendOperation<T, Name>` instead. Here, `T` is the **prepared output**: finite declared type, `Records<Format, Item>` for typed streaming, `Incoming` for untyped streaming, or `()`. See [emit.rs:1865](/home/canarit/projects/Concord_Desirability_Loop/work/wt/h01s/crates/concord-macros/src/emit.rs:1865), [emit.rs:1915](/home/canarit/projects/Concord_Desirability_Loop/work/wt/h01s/crates/concord-macros/src/emit.rs:1915), and [emit.rs:1971](/home/canarit/projects/Concord_Desirability_Loop/work/wt/h01s/crates/concord-macros/src/emit.rs:1971).

The declared send result is **the complete policy output**, not its success payload. `_` substitutes the whole prepared output; the generator emits an equality constraint, not a conversion. `SendWith::Output` itself is unrestricted—it need not be a `Result`. `Sends<O>` exposes that same complete output generically. **4. What could be measured**

Prefer these automatic checks before another reader pilot:

1. **Independent result-identity checks per endpoint.** Compile a function accepting the generated endpoint and constrain `endpoint.send()` with `Future<Output = Expected>`. Obtain fully qualified `Expected` from a reviewed SDK contract manifest—not from the same generator producing the docs. Check the success shape and error owner separately. Add deliberate wrong-owner/wrong-wrapper cases to verify that the instrument rejects them.
2. **Rustdoc JSON contract checks.** Compare the documented result with the generated method’s future output; resolve aliases/projections and error-definition identities. Check endpoint, navigation and `send()` docs together. Record whether the concrete type is available on that page or requires following a policy/format implementation.
3. **Public API and caller-expression comparison.** For aliases, require unchanged underlying identities. For representation changes, compare every affected annotation, match, field access and `Sends<O>` bound against the preregistered breakage list. Keep private wire results distinct from public facade results.
4. **Preservation checks using existing fixtures.** Relevant test sources already cover [Cloudflare envelope authority](/home/canarit/projects/Concord_Desirability_Loop/work/wt/h01s/examples/cloudflare-zones-sdk/tests/protocol.rs:171), [Linear partial diagnostics](/home/canarit/projects/Concord_Desirability_Loop/work/wt/h01s/examples/linear-sdk/tests/protocol.rs:226), and [PokéAPI metadata after body failure](/home/canarit/projects/Concord_Desirability_Loop/work/wt/h01s/examples/pokeapi-sdk/tests/protocol.rs:180). These are proposed validation inputs, not results obtained here.

Use **Cloudflare plus Anthropic** as unlike primary witnesses: envelope projection versus associated stream-reader opacity. Kraken, MediaWiki and World Bank extend projection coverage. Use **Xero as a contrary case**: its public `.send()` already names `InvoicePage`/`Invoice`; changing internal generated docs cannot improve that public signature. GitLab is another clear-result comparison.

Keep **Nager, PokéAPI and Frankfurter** as controls: preserve their existing call expressions, SDK error ownership and named success fields without required extra steps. A1 makes added required ceremony on these controls a default kill. [A1:57](/home/canarit/projects/Concord_Desirability_Loop/PLAN_AMENDMENT_A1.md:57).

Only if type accuracy is equal but findability remains unresolved should readers predict the exact awaited type, error owner, metadata path and stream/page exception. Score those facts separately. A3 explicitly prefers compiler/static evidence and suspends ceiling-level regression reader runs. [A1:40](/home/canarit/projects/Concord_Desirability_Loop/PLAN_AMENDMENT_A1.md:40), [A3:66](/home/canarit/projects/Concord_Desirability_Loop/PLAN_AMENDMENT_A3.md:66).
