## Problem
As `cards/H03.md`. New fact from the H03 reviews: no exact-type design keeps every spelling that
compiles today — generic code bounded by `IntoValue<T>` (or an opaque `impl IntoValue<T>` value)
cannot be equated with `T`, so H03's kill condition excludes the whole design space. H03b asks
whether the inference gain is worth an enumerated break with a mechanical migration.

## Compatibility contract (replaces H03's kill condition "any newly rejected caller spelling")
A candidate may newly reject only these spellings; each class is listed in `docs/MIGRATION.md`
with its mechanical migration, and every repository site in a class is listed:
- **K1 — borrowed forms into a non-lexical `String`/`HeaderValue`.** A borrowed `&str` / `&String`
  / `&HeaderValue` passed where the declared type resolves to `String` / `HeaderValue` but is
  written under another final path segment: an alias (`type Raw = String`), a renamed import
  (`use … HeaderValue as Native`), a qualified alias (`module::Raw`), a generic alias, an
  associated-type projection, or a type macro. (Paths keeping the final segment `String` /
  `HeaderValue` — `std::string::String`, `reqwest::header::HeaderValue`, re-exports — keep
  converting.) Migration: pass an owned value (`.to_owned()`, `.clone()`), or declare the input as
  `String` / `HeaderValue`.
- **K2 — generic or opaque values into an input that becomes exact.** Caller code generic over
  `V: IntoValue<T>`, or an opaque `impl IntoValue<T>` value, passed to an input that now takes
  exactly its declared type — for any declared `T` (numbers, newtypes, bodies, `Option<…>`,
  `Cow<…>`, and aliases resolving to `String` / `HeaderValue`). Concrete values of the declared type
  stay accepted; the baseline offered no `Option` wrapping or `Cow` conversion, so none is lost.
  Migration: call `IntoValue::into_value(v)` at the call (keeps the adapter's generic signature),
  or take `T`.
- **K3 — function values instantiated through K1 or K2.** Migration: a forwarding closure or
  wrapper applying the K1/K2 migration.
- **K4 — hand-written implementations of a generated parameter-group trait whose setter becomes
  exact** (both arms). Migration: take `T` in that setter.
The permissions K1–K4 waive nothing else: zero corpus regressions, no caller change in the
controls (Nager, PokeAPI), unchanged provider semantics and wire behaviour, North-star (A5) and
counterexamples (A6) all still hold. Required: in the 55 SDKs (sources, tests, docs, examples) the
migration build shows no rejected spelling outside K1–K4, each site listed with its class; outside
the SDKs, the four H03 fixture sites (`examples/renamed/src/lib.rs:30` K1, 
`crates/concord/tests/native_headers.rs:155,292` K1, `crates/concord/tests/formats.rs:372-373` K1)
and any other site, each listed with its class.

## Decision (copied from H03; the compatibility clauses changed as stated)
- **WIN (A′ or B′):** on the witnesses the corpus success rate rises by ≥ 20 points over baseline
  and every witness gains ≥ 1 newly working spelling; 0 corpus regressions on any SDK (witnesses,
  contrary case, control); Nager and PokeAPI need no caller change; I5: no case newly names
  internals and every `wrong_setter` first error names the expected type; existing tests and
  sources change only at sites the change requires, each listed with its K class; every newly
  rejected spelling belongs to K1–K4 and is migrated and documented; guardrails and gates pass.
- **B′ instead of A′:** only if B′ meets every A′ condition and also removes Concord's internal path
  from the remaining E0283 labels (I5) without new breakage (this requirement is unchanged from H03
  and is not relaxed by B′'s narrowing to inherent methods).
- **KEEP_CURRENT:** the corpus gain is < 20 points, or comes with regressions the alternatives
  cannot avoid (regressions here mean corpus regressions, control caller changes, wire or semantic
  changes, A5/A6 losses — not K1–K4 rejections).
- **LOSS:** a gate failure; any corpus regression; a `wrong_setter` diagnostic that no longer names
  the expected type; a required caller change in a control; a newly rejected spelling outside K1–K4.
- **INCONCLUSIVE:** gains on only one witness; corpus or harness cannot be built for a witness.
- A WIN leads to full migration (every SDK, the docs that state the conversion rule, the UI tests
  whose expected errors change, the `IntoValue` doctest, `docs/MIGRATION.md`, `CHANGELOG.md`, the
  55-row impact table), the broad gate and CI, before ACCEPT.

## Concept budget (per arm; A1 counts developer rules)
- Baseline rules: (r1) every input is generic: target-typed spellings (`Default::default()`,
  `.into()`, `.parse()`) need the type named or a turbofish; (r2) `String` inputs also take
  `&str`/`&String`, `HeaderValue` inputs `&HeaderValue`; nothing else converts.
- **A′:** removes r1 for every input not declared `String`/`HeaderValue`; changes r2 to a lexical
  rule (the borrowed forms follow the written final segment `String`/`HeaderValue`, not aliases;
  those inputs keep r1). Net **0** (−1 rule, +1 lexical qualification). Budget: 0.
- **B′:** A′ + (r3) inherent methods' converting inputs have public named generic parameters (the
  value name in UpperCamelCase, collision suffix rule, argument order; turbofish possible). Net
  **+1**. Budget: +1 rule — a prospective change from H03's "0 new public concepts", disclosed here
  before any result; B′ must still meet the unchanged "B instead of A" condition.
- No new DSL keyword, statement, public trait or public type in `concord-core`/`concord-macros`.

## Kill conditions
Defaults (DECISION_RULE) + a newly rejected spelling outside K1–K4; a change to how a value is sent.
