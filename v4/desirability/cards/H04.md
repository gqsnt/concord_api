## Sample and procedure

Materials (both arms, same extraction, same nightly rustdoc): the task text, the cheat sheet at
B, the SDK's **public** generated rustdoc rendered to text from the arm's commit, and the arm's
package README unless the crate page already contains it; worked examples are removed in every
format in both arms (every code block of any fence or indentation becomes a placeholder; inline
code holding an expression is removed; bare type/item names stay) and every endpoint call chain
written in prose is removed (I3's chain rule); format-conversion and per-SDK coverage audits
must hold for both arms; no `api!` declaration, no source. **Materials clearance gate (fail closed):** for every SDK whose candidate
materials differ from the baseline arm's, a full unified diff (additions, deletions, both ends of
moves, whitespace and structure preserved) is written out, and reader prompts are built only when
the candidate's independent review has read the diffs and cleared the exact SHA-256 digests of the
complete candidate materials (per SDK and overall): nothing in them supplies a task answer. Any
later change to the candidate materials requires a new clearance. Each arm is rendered from its
commit in its own build directory with provenance-checked rustdoc; the template and cheat sheet
must equal the digests approved in the sealed bank; a run freezes (schedule, manifest, prompts) at
its first session, and resume and scoring refuse anything that differs. Call answers compile as an
integration test of the SDK package (public API only). Readers run in bubblewrap with the home
and the repository hidden, a fresh provider home holding only the credential file, an empty
working directory; transcripts are checked (tools, skills, instructions) and a failing session
is discarded. Runs and prompts are kept sealed (`work/sealed/h04-runs/`). Claude readers
`claude-opus-5-5` (effort not passed, no tools, no setting sources), Codex `gpt-6.1-sol` xhigh
read-only (strict config, no plugins/skills, owner service tier).
Materials per arm: the same task text, public types, the cheat sheet, and the SDK's generated
rustdoc rendered to text from that arm's commit (same extraction for both). Readers see no source,
tests, records or other answers. Two providers (Claude `claude -p` no tools; Codex
`gpt-6.1-sol` xhigh read-only), three fresh repetitions per SDK and arm, four answers per session:
72 sessions, 288 answers, interleaved in a randomised balanced order; observed models recorded.
First answers kept; no recovery round in this pilot.

## Target outcome and decision (thresholds frozen here; pilot triage rules, not statistics)
- Primary outcome: *discover the contract* + *complete ordinary use* (A1 §2.2), scored per task,
  SDK and provider; critical-fact failures (wrong destination, false result/error claim, exposed
  tenant control, wrong recovery rule) reported separately.
- **Gates:** no false public claim; no behaviour/API change; Xero tenant checks and Kraken signing
  semantics preserved; rustdoc builds with `-D warnings`; published doc examples pass; the full
  gate and CI on the exact candidate; independent review validates docs-only scope.
- **WIN:** ≥ 6 net additional correct answers among the 72 candidate witness answers; neither
  provider has a negative net witness change; controls lose ≤ 2 of their 72 answers and no critical
  contract fact is newly misrepresented; no recurrent new critical-task failure in any SDK.
- **LOSS:** a gate failure, a repeated substantive regression attributable to the candidate, or no
  useful improvement with increased caller obligations.
- **INCONCLUSIVE:** a smaller gain, provider disagreement, a ceiling, or missing oracle/tooling;
  the baseline is kept unless a narrower deterministic correction (a false statement fixed)
  independently justifies adoption under the docs-truth path.
- One-provider run (if a provider fails): halved sample, labelled provisional, cannot WIN.
- Rule readings fixed in `decision.py`: control losses count regressions (not net); "recurrent" =
  ≥ 2 regressions in one SDK/task or one control fact (applies in addition to the next rule); a control critical fact that passes in
  every baseline-arm session of its SDK (both providers, all repetitions) and fails in at least
  one candidate session is **newly misrepresented** and blocks WIN (INCONCLUSIVE, or LOSS when
  attributed to the candidate docs); gate outcome (including the docs-truth gate: no critical
  control fact misrepresented in the candidate docs, from the candidate's independent review),
  increased caller obligations and attribution of a regression are recorded inputs; a WIN is
  reported WIN_PENDING_GATES until every gate is known.

## Limits
The pilot measures text content and information hierarchy with model readers; it does not
measure worked examples (removed in both arms), visual layout, or human preference.

## Concept budget
0 new public concepts (docs only). Diagnostics only: rustdoc words per endpoint (R4c), page
length.

## Kill conditions
Defaults (DECISION_RULE) + any behaviour or signature change; any false statement in generated
docs; the simple control's call becomes harder (more required reading to find it).

## Affected SDKs
All 55 (generator change) on WIN: their generated docs change, no source change. Migration =
regenerate + rustdoc `-D warnings` + doc tests; no caller-visible change; CHANGELOG entry
(documentation).
