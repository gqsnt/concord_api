# H16 Request composition is predictable from the docs a caller sees (docs-only)

Family: REQUEST
Status: PRE-REGISTERED on `concord-desirability` before any implementation. Thresholds below are
frozen; no candidate exists. Survey: `reviews/h16-design-survey.md` (base `f921b002`).
Decision path: design hypothesis (PLAN_AMENDMENT_A1 §3), docs-only pilot (like H04); pilot, then migrate.

## Problem (measured on the current head, 2026-11-09, before this card)
I3 R1 (request prediction, `wire` session), fresh readers on the code of `f921b002` (H04's doc change
included; `work/dev/h16/i3-current`, `work/tools/h16_deficit_check.sh`): readers still mispredict
request composition, with the baseline's pattern:
- **query order** — an endpoint's fixed query pair is sent after the caller's values; readers place it
  first: Kubernetes R1.critical 6/6, 3/6, 3/6 (Codex run 1, Codex run 2, Claude); MediaWiki 3/3, 3/3, 0/3;
- **path-value encoding** — Nager's path value is percent-encoded per segment: 1/1, 1/1, 0/1;
- **format-implied headers** (R1.exact; `Accept` and header names/values): FRED 4/6 in every run
  (`Xml` sends `accept: text/xml`), ClickHouse 0/1 in every run, OpenAI 2/3 in every run, Backblaze B2
  2/3 (Codex) and 3/3 (Claude).
- Controls (PokeAPI, Frankfurter) and the contrary case (World Bank) are correct in every run.
Readers: Codex `gpt-6.1-sol` xhigh (as the baseline); Claude `claude-opus-5-5` at effort medium (owner
A3.2; weaker than the baseline's default effort). The rules exist (SEMANTICS, AUTHOR_GUIDE) but the docs
a caller reads at the endpoint do not state them where the prediction is made.

## Comparator
- **Baseline:** the head carrying this card (generated docs as after H04).
- **Alternative A (docs only):** generated endpoint/navigation docs state the composition facts a caller
  needs: the query order (inherited fixed pairs, the endpoint's fixed pairs, caller values, groups and
  `query(..)` positions, in the order sent, with the fixed values); path holes with their encoding (each
  value is one percent-encoded segment; the escape set); and where `Accept`/`Content-Type` come from
  (the declared format, with the format's declared value where the macro can see it), plus SDK-local
  notes where the macro cannot (custom format constants such as FRED's, public wrapper headers such as
  ClickHouse's and B2's), each checked against source. No change to generated code other than doc
  attributes; no wire change.

## Outcomes (A1 §2.2) and instruments
Primary — **discover the contract (request prediction):** I3 R1 on the `wire` sessions of the 10 SDKs
above (23 witness items, 4 control/contrary items), both arms, **3 fresh repetitions per provider per
arm** (Codex `gpt-6.1-sol` xhigh; Claude `claude-opus-5-5` effort medium), arms interleaved per
repetition; truth regenerated per arm commit; scored by `tools/desirability/probes/score.py`
(R1.critical = method + destination + query; R1.exact = all request fields). Paired by item and
repetition; results per provider, SDK and item.
Secondary (static, diagnostic): for every endpoint in the 55 SDKs with fixed query pairs, path holes or
a format-set header, whether its generated docs state the fact (count before/after).
Costs (gates where bounded): public rustdoc JSON identical apart from docs for every crate; generated
code identical apart from doc attributes (expansion diff); doc-text assertions and snapshots that change
(listed); full gate and CI Linux/Windows on the merged commit; one combined independent review (A3 §5).

## Decision (thresholds frozen here; pilot triage rules, not statistics)
Let W = correct (item × repetition) counts on the 23 witness items, pooled over the 3 repetitions per
provider (69 per provider), for R1.exact (which implies R1.critical).
- **WIN (A):** W rises for **both** providers and the pooled rise is ≥ 10 (of 138); no witness SDK
  falls for either provider; the 4 control/contrary items stay correct in every repetition of the
  candidate arm (or match the baseline arm's count, if the baseline arm misses one); docs-only proven
  (rustdoc JSON identical apart from docs; expansion identical apart from doc attributes); gates pass.
- **KEEP_CURRENT:** the pooled rise is < 10, or only one provider rises.
- **LOSS:** a control/contrary regression beyond the baseline arm's own misses; any non-doc change to
  generated code or public API; a gate failure.
- **INCONCLUSIVE:** the baseline arm reaches ≥ 66 of 69 for both providers (ceiling: no room for the
  threshold), or the instrument cannot score an SDK.
- A WIN leads to full migration (the docs rules apply to every SDK automatically; SDK-local notes for
  every custom format constant and public wrapper header — listed), the broad gate and CI, before ACCEPT.
