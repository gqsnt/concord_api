# H06 Generated controls match intended use: an author can withhold a control that breaks the SDK's invariant

Family: SURFACE
Status: PRE-REGISTERED on `concord-desirability` before any implementation (PLAN_AMENDMENT_A3: two
hypotheses in flight — H06 is N+1 while H03b is measured). Thresholds below are frozen; no
candidate exists. Survey: `reviews/h06-design-survey.md` (base `a883f7bb`). Scope representation
(flattening, scope capabilities — survey §4, option H) is split off as **H06b** (queued); this card
covers construction and controls only.
Decision path: design hypothesis (PLAN_AMENDMENT_A1 §3); pilot, then migrate.

## Problem (recorded / checked against source)
- Every generated control is unconditionally public: `set_x`/`maybe_x` for every client and scope
  value (required ones included), `with_base_url` (keeps every value, credentials included,
  `crates/concord-macros/src/emit.rs:1723-1736`), `set_policy`; the only visibility is the client's
  `vis`, applied to the whole declaration (emit.rs:16-43). An SDK can withhold a control only by
  hiding the entire generated surface behind a hand-written facade (14 SDKs hide their generated
  client; 120 mechanical wrapper items in 42 SDKs, survey §2).
- Public controls that contradict the SDK's own documented invariant (checked in source; behaviour
  at the wire is the baseline measurement's job):
  - **Shopify**: scope `shop(shop, #[sensitive] access_token)` — "Tokens are per shop"
    (`examples/shopify-sdk/src/api.rs:35-40`); `ShopifyAdminShop` is re-exported (lib.rs:46) and
    returned by `ShopContext::admin()` (context.rs:120): `set_shop(other)` keeps shop A's token.
  - **Zendesk**: client values `subdomain` + `#[sensitive] authorization` (lib.rs:42-54), public
    generated client: `set_subdomain(other)` keeps the token.
  - **Salesforce**: public generated client `SalesforceApi(#[sensitive] token, version)` with a
    placeholder base (api.rs:39-41; `pub use api::*` lib.rs:65), handed out by `OrgContext::api()`
    (context.rs:112): `with_base_url(other)` keeps the token; `set_version(v)` bypasses the
    `version ≥ ApiVersion::MINIMUM` check `OrgContext::new` enforces (context.rs:85-93).
  - **Mastodon** hides its whole generated client to withhold `with_base_url` (token bound to the
    instance), at the cost of an unnameable client and a placeholder host in its docs
    (`FRICTION.md` §1); Xero does the same for its tenant scope (`FRICTION.md` F2: "an opt-in
    generated API view that omits context/base setters").

## Comparator
- **Baseline:** the head carrying this card (every control public; withholding = hide everything).
- **Alternative A — fixed values:** an attribute on a client or scope value making it supplied
  once (construction or scope entry) with no generated `set_x`/`maybe_x`. Does not cover built-in
  controls (`with_base_url`, `set_policy`).
- **Alternative B — control visibility:** the author declares, per generated control (value
  setters, `with_base_url`, `set_policy`), whether it is public (default), crate-visible, or not
  generated. Default unchanged (opt-in).
Pilot adoption (both arms, as far as each arm can express it): Shopify (shop not replaceable on the
scope), Zendesk (subdomain not replaceable on the client), Salesforce (base and version not
replaceable by callers; `OrgContext` keeps its validated constructor), Mastodon (B only: publish
the generated client with the base withheld).

|---|---|---|---|
| Shopify | witness (scope value) | FM1 `admin().clone().set_shop(b)` keeping the token | another shop via a new `shop(b, token_b)` entry; same-shop token rotation (`set_access_token`); first call |
| Zendesk | witness (client value) | FM2 `set_subdomain(other)` keeping the token | `connect(other, token)`; `set_policy` (documented, `policy.rs:28`); first call |

## Outcomes (A1 §2.2) and instruments (A3 §7: compiler and static evidence first)
Primary — **trustworthy construction:** per FM, whether the move is available to a caller (a
compile probe outside the SDK crate) and, if it compiles, the stage that rejects it (construct /
build / send before I/O / never) and the request count at a second "evil" local server (must be 0).
Per VM: compiles and sends the intended request at the local receiver. Probes are task files for the
pilot harness (`tools/desirability/pilot/`, A3 §2), written by a measurement lane after the
candidates freeze; baseline run first (a listed FM that the baseline already rejects is reported and
leaves the denominator).
Secondary — **complete ordinary use:** construction + first call for each witness from its public
docs compiles and sends the intended request (method, path, host, sensitive auth header).
Costs (gates where bounded): public rustdoc JSON diff (adopters change only as listed under
Expected breakages; non-adopters and controls identical apart from docs); concept count; call sites
changed; `benches/scale/ab.sh` compile time and expanded size within +5%; full gate and CI
Linux/Windows on the merged commit; one combined independent review (A3 §5).

## Decision (thresholds frozen here; pilot triage rules, not statistics)
- **WIN (A or B):** every FM1–FM4 is unavailable at compile time, or rejected before I/O with 0
  requests at the evil server; every VM of every witness and contrary case still compiles and sends
  the intended request; Mastodon's host move stays unavailable; controls and non-adopters unchanged
  (public API identical apart from docs); concept budget met; A7 met (removes a misleading or unsafe
  public item from ≥ 2 SDKs); guardrails and gates pass.
- **B instead of A:** only if B meets every A condition and also lets Mastodon publish its generated
  client with the host move unavailable (the client nameable in its public docs, the placeholder
  host no longer the documented destination of a callable constructor), with fewer hand-written
  forwarders (listed; diagnostic).
- **KEEP_CURRENT:** neither arm makes all of FM1–FM4 unavailable without losing a VM.
- **LOSS:** any VM lost (rotation, coordinated replacement, documented `set_policy`, a valid
  replacement route); a control gains ceremony or changes API; a breakage outside the list below; a
  gate failure; a wire change for any non-withheld call.
- **INCONCLUSIVE:** a probe cannot be built for a witness; the baseline already rejects most FMs.
- A WIN leads to full migration (every SDK whose documented invariant a public control contradicts —
  candidates from survey §3: Discord/Sentry/Adyen credential+state pairs, DigitalOcean's
  `for_fixture`, QuickBooks `new` vs `connect`, Xero — each decided per SDK in the impact table),
  docs (AUTHOR_GUIDE, SEMANTICS, CHANGELOG, MIGRATION), the broad gate and CI, before ACCEPT.

## Expected breakages (A3 §8; anything else is a kill)
- **E1 Shopify:** `ShopifyAdminShop::set_shop` / `maybe_shop` no longer public (replacement: a new
  `shop(b, token_b)` entry). `set_access_token` stays.
- **E2 Zendesk:** the generated client's `set_subdomain` / `maybe_subdomain` no longer public
  (replacement: `connect(other, token)`).
- **E3 Salesforce:** `SalesforceApi::with_base_url`, `set_version`, `maybe_version` no longer public
  to callers (replacement: `OrgContext::new`); arm A cannot withhold `with_base_url` (it then fails
  FM3; that is a measured outcome, not a breakage).
- **E4** tests and docs inside those three SDKs that call a withheld control change to the
  replacement route, each site listed.
- **E5 Mastodon (B):** no caller-visible removal; new public items (the generated client and its
  handles) are listed.
- **E6** macro: the new attribute or visibility form (one), its UI tests and docs.

## Concept budget
≤ 1 new author-facing rule (A: one value attribute; B: one per-control visibility form). No new
public trait or type in `concord-core`/`concord-macros`. Caller-facing concepts: none (fewer
controls in adopting SDKs).

## Kill conditions
Defaults (DECISION_RULE) + any breakage not listed under E1–E6; any VM lost; a change to how a
non-withheld call is sent.
