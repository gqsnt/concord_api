# H09c A resume position is constructible from the docs at the resume methods

Family: CAPABILITY (traversal resume)
Status: PRE-REGISTERED on `concord-desirability` after the H09a baseline (`measurements/H09a-baseline.md`) and
its review (`reviews/h09a-baseline-review-sol.md`: REJECT of "not carded"; narrow import-discovery card). No
candidate exists when this card is committed. Thresholds and the outcome mapping below are frozen before any
candidate or run. Decision path: design hypothesis, docs-only pilot covering every affected method (A1 §3, A3 §7).

## Problem (measured)
H09a baseline round 2 (materials with the linked `concord_pagination` definitions a docs.rs reader reaches):
resume tasks Codex 37/42, Claude 42/42; fresh traversals 33/33 each. All five Codex resume misses (GitLab in
3 of 3 repetitions, Distribution Registry 2) and one Stripe supplement miss are the same compile failure: the
position is written as `concord::pagination::Resume`, a path that does not exist; the resume methods' docs
name `Resume` without saying which path a caller writes or how to build one, and 9 of the 12 twin SDKs do not
re-export it (the caller names a second crate, `concord_pagination`).

## Claim and comparator
Claim: when every public SDK method that takes a `Resume<K>` states, in its own docs, the path a caller writes
for the position (`concord_pagination::Resume`, plus the dependency to add — or the SDK's re-exported path where
one exists) and its two constructors (`Resume::Start`, `Resume::At(key)` with what `key` is for that method),
readers construct resume calls that compile and behave as intended more often.
- Baseline arm: this card's commit. Candidate arm: the same API with that guidance — documentation only (doc
  comments and SDK READMEs of the affected SDKs). Re-exports, new methods or any API change are **out of scope**
  (a separate card, only if this docs-first comparator fails).
- Witnesses: the resume tasks of the 12 twin SDKs (Cloudflare Zones, Datadog Events, DigitalOcean, Discord,
  Distribution Registry, GitHub, GitLab, Mailgun, Microsoft Graph, Notion, Spotify; Stripe reported separately
  as the supplement). Controls: their fresh-traversal tasks, the Mailgun contrary item (edge), PokeAPI simple
  resume/fresh, Stripe supplement fresh.

## Instrument (frozen)
The H09a bank (`h09a-bank`, set `d81d3df1…`, unchanged), `h09a/notion/02` excluded (known defect: its text does
not state a value its key requires). Materials per arm = the round-2 method (H04 v1 renderer + linked
`concord_pagination` definitions, `prepare_linked.py`), rendered at each arm's commit. Paired pilot schedule
(`pilot.py reader-pack`, both arms, seed 20261109), **5 repetitions per provider per arm** (Codex `gpt-6.1-sol`
xhigh; Claude `claude-opus-5-5` effort medium, owner A3.2). Answers compile at the bank's compile commit
`475a7867` for both arms (valid because the candidate must be docs-only: checked by rustdoc JSON of the affected
crates identical apart from docs). Scored by `pilot.py reader-score` (R3 sandbox). Counts per provider over
5 repetitions: resume R = 14 scored tasks × 5 = 70; Stripe supplement 5; fresh 55; edge 5; PokeAPI 5 + 5.

Exposure check, before any reader runs: the candidate arm's materials contain the new guidance for every twin
SDK's resume methods, and the two arms' materials differ only in the docs the candidate changed.

## Decision (frozen; evaluated in this order — the first that applies is the outcome)
1. **LOSS** — any of: a non-doc change (rustdoc JSON of an affected crate differs other than in docs, or any
   code/test/API change beyond doc-text assertions); for either provider, a control class (fresh, edge, PokeAPI
   simple resume, PokeAPI simple fresh, Stripe supplement fresh) falls by more than 1 versus the baseline arm;
   Claude resume falls by more than 2; a gate failure.
2. **INCONCLUSIVE** — the exposure check fails; or the baseline arm's Codex resume is ≥ 67 of 70 (ceiling: no
   room for the threshold).
3. **WIN** — Codex resume rises by ≥ 5 of 70 (candidate − baseline); Claude resume falls by at most 1; no
   witness SDK falls by more than 2 for either provider.
4. **KEEP_CURRENT** — everything else (including a Codex rise below 5, a Claude fall of exactly 2, or a witness
   SDK falling by more than 2 without a LOSS condition).
- Reader variability is reported per SDK and class as the spread across the 5 repetitions of each arm; the
  Stripe supplement is reported, not pooled into R.
- A WIN covers every affected method by construction (the candidate documents every public `Resume`-taking SDK
  method in all 55 SDKs); it then needs the gate and CI on the merged commit, before ACCEPT.

## Expected breakages (A3 §8)
None at the API or wire level. Doc-text assertions or doc snapshots of the affected SDKs may change (the
candidate lists them).

## Kill conditions
Defaults + any change other than documentation (no re-export, method, signature, type or behavior change);
any control regression as defined in outcome 1.
