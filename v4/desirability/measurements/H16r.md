## The one clause that fails
The card's WIN requires, for each provider, that no witness SDK falls by more than 2 item-runs.
**Codex OpenAI falls by 3** (13 → 10), all on item `openai/w1` (binary file content, no Accept set by the SDK
or Concord): the candidate arm reports `accept` = reqwest's default `*/*` in all 5 repetitions; the baseline
arm missed the same field in 2 of 5 (a guessed format value). Claude misses it once in the candidate arm.

Observation behind it, not a decision input: the question asks for "the request the server receives" and
restricts `headers` to those the SDK and Concord set, while the key scores `accept` as the Accept the SDK and
Concord set (none here). The candidate's generated header note and OpenAI's SDK-local note both state, truly,
that reqwest fills a missing `accept` with `*/*` at execution; read with the "server receives" wording, that
answer is defensible. This is an interaction between a true candidate statement and an ambiguous field of the
instrument; it is recorded, and it does not change the frozen clause.

kept unchanged.
