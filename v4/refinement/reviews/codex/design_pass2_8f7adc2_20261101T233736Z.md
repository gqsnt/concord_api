The following findings determine my priorities.

1. **Confirmed robustness defect: header construction does not cover native failure conditions.**

   The supplied L1 lead reproduces: a declaration containing a 65,536-byte header name compiles, then `prepare()` panics in `HeaderName::from_static`.

   The relevant paths are [name validation in model.rs](/home/canarit/projects/concord_v4_refine_work/snapshots/codex-design-8f7adc2/crates/concord-macros/src/model.rs:752) and [header construction in __private.rs](/home/canarit/projects/concord_v4_refine_work/snapshots/codex-design-8f7adc2/crates/concord/src/__private.rs:254).

   There is an additional capacity path. With locked `http 1.5.0`, native `try_append` returned `MaxSizeReached` at distinct-name index **24,576**. Concord’s `Parts::header` panicked at that boundary because it calls `append`.

   This capacity reproduction was a **white-box runtime-helper probe**, not a generated declaration containing 24,577 headers. It establishes the helper’s failure behavior; a generated boundary fixture remains useful.

   The smallest correction is complete declaration-time name validation plus fallible map insertion. Cover both ordinary headers and the body’s fallback `Content-Type` insertion at [__private.rs:334](/home/canarit/projects/concord_v4_refine_work/snapshots/codex-design-8f7adc2/crates/concord/src/__private.rs:334). Return a value-free build error. I did not inspect the coordinator’s separate fixes and cannot certify them.

2. **Confirmed contract mismatch: cross-name header order is overpromised.**

   [SEMANTICS.md:137](/home/canarit/projects/concord_v4_refine_work/snapshots/codex-design-8f7adc2/v4/SEMANTICS.md:137) connects header slots with first-appearance ordering. [The wire test](/home/canarit/projects/concord_v4_refine_work/snapshots/codex-design-8f7adc2/crates/concord/tests/composition.rs:471) asserts a sequence spanning `x-tag` and `x-other`.

   The prefetched native `HeaderMap` documentation explicitly makes iteration order arbitrary. The current test passed, but that does not establish the promised contract.

   Retain exact query ordering and same-name header value behavior. Remove cross-name header-order assertions and promises. This agrees with supplied L2; it does not justify changing query composition.

3. **Demonstrated ownership cost: COW edits can clone unrelated payloads.**

   The probe retained a 1 MiB clone-counted value. Root/scope handle copies caused zero payload clones. Editing an unrelated field while root state was shared caused one payload clone. Cloning a bodyless endpoint caused another clone of its endpoint-local payload.

   This follows [Arc::make_mut controls](/home/canarit/projects/concord_v4_refine_work/snapshots/codex-design-8f7adc2/crates/concord-macros/src/emit.rs:242) and [body-dependent Clone generation](/home/canarit/projects/concord_v4_refine_work/snapshots/codex-design-8f7adc2/crates/concord-macros/src/emit.rs:355).

   These are real costs, not timing or allocation measurements. Current semantics already disclose Clone requirements. Documentation should additionally explain when cloning occurs and that snapshots are structural: the interior-mutation probe showed an existing child observing a later mutation inside caller-owned shared data.

4. **Demonstrated ergonomic gap: native edits lose Concord’s transport-error conversion.**

   Current `into_parts()` preserves the decoder, and native timeout/header edits worked. However, the documented route uses native `execute(...).await?` before `Decoder::decode`; transport failure then belongs to the application’s native error boundary.

   Concord’s protected conversion is private: [error.rs:64](/home/canarit/projects/concord_v4_refine_work/snapshots/codex-design-8f7adc2/crates/concord/src/error.rs:64). The public decoder accepts only a successful native response: [prepared.rs:121](/home/canarit/projects/concord_v4_refine_work/snapshots/codex-design-8f7adc2/crates/concord/src/prepared.rs:121).

   A copied-runtime prototype added:

   ```rust
   pub async fn finish(
       self,
       result: Result<reqwest::Response, reqwest::Error>,
   ) -> Result<R::Output, Error>
   ```

   It applies existing protected transport conversion, then existing decoding. Three prototype tests passed: native-base consistency, protected connection failure, and successful decoding. This is sufficient evidence for a small convenience candidate, not an `ApiResponse` framework.

        }

}
