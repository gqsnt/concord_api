The strongest opportunities are **clearer generated URL documentation, one opt-in transport builder, and selective removal of generated mutation APIs**. The sweep does **not** support a universal host abstraction or moving provider URL trust into Concord.

I inspected all **55 SDKs**, their available FRICTION/FIRST_USE/MAINTENANCE records, and the relevant Concord implementation. There are **63 client declarations**. I made no changes, ran no builds or tests, and used no external services.

**Most valuable findings**

1. **The generated documentation conceals a distinction consumers repeatedly need.**

   Concord replaces the complete declared `base`, including its path, and appends declared `path` components. The author guide states this clearly at [`AUTHOR_GUIDE.md:256`]( /home/canarit/projects/Concord_SDK50_Ecosystem_Handoff/work/integration/docs/AUTHOR_GUIDE.md:256), but endpoint rustdoc renders one composed URL and calls it “the declared base URL”: [`emit.rs:892–945`]( /home/canarit/projects/Concord_SDK50_Ecosystem_Handoff/work/integration/crates/concord-macros/src/emit.rs:892).

   Five fresh consumers recorded incorrect predictions or failed requests:

   - Airtable duplicated `/v0`: `FIRST_USE.md:35–44,152–159`.
   - Cloudflare duplicated `/client/v4`: `FIRST_USE.md:99–108,130–134`.
   - Zendesk duplicated `/api/v2`: `FIRST_USE.md:128–132`.
   - NASA removed `/neo/rest/v1`: `FIRST_USE.md:117–124`.
   - Sentry incorrectly predicted removal of `/api/0`: `FIRST_USE.md:44–47,153–155,238–244`.

   OpenAI’s author independently recorded losing `/v1` before moving it into `path`: `FRICTION.md:10`; current declaration `src/lib.rs:27–28`.

   **Inference:** improving generated documentation has stronger cross-domain evidence than changing URL composition.

2. **Twenty-two SDKs repeat precisely the same two transport settings.**

   Their cited transport blocks occupy **169 physical lines**. Only **44 lines**—22 redirect settings and 22 native-retry settings—are the common removable part. Timeouts, referrer policy, proxy behavior, decompression, validation, and error conversion differ.

   Three other SDKs disable redirects without disabling native retries: **Amazon S3, ClickHouse, Microsoft Graph**. GitHub and GitLab instead provide same-origin redirect policies. These are distinct contracts.

3. **Generated mutation is sometimes incompatible with the SDK’s ownership boundary.**

   `with_base_url` changes only `__base`; it retains credentials and policy values. Required values also receive setters. This is directly visible in [`emit.rs:741–782`]( /home/canarit/projects/Concord_SDK50_Ecosystem_Handoff/work/integration/crates/concord-macros/src/emit.rs:741) and [`emit.rs:1429–1439`]( /home/canarit/projects/Concord_SDK50_Ecosystem_Handoff/work/integration/crates/concord-macros/src/emit.rs:1429).

   Mastodon explicitly hides the generated client to prevent moving an instance token (`src/api.rs:1–4`; F31–60). Xero explicitly hides generated tenant/context setters (F15–23). Graph combines a private generated client with destination and authorization-context checks (F33–46).

   **Inference:** an opt-in way to generate fewer controls is justified. A runtime base alone would not establish credential ownership or remove these SDKs’ domain checks.

4. **Existing `Prepared::follow` already covers most exact provider URL execution.**

   Nine SDKs use it: **B2, DigitalOcean, Distribution Registry, GitLab, Google Drive, Mailgun, Microsoft Graph, PokéAPI, Snowflake**. There are **17 call sites**: 16 for provider targets and one Registry digest-path rewrite.

   GitHub still performs a native URL edit for pagination even though its existing validation can precede `Prepared::follow`. Salesforce and Sentry validate and reconstruct typed operations instead. Cross-origin Shopify and GitHub downloads deliberately create separate requests without API credentials.

**What Concord could remove or shrink**

- **Stop generating unusable controls when authors opt out.** The important subtraction is selected base/context mutation, not removal of all setters. Mastodon F31–60 and Xero F15–23 provide direct evidence.
- **Shrink generated documentation that exposes irrelevant construction internals.** PayPal’s public docs expose `new`, `PayPalConfig`, and `set_session`, although callers cannot construct the required session themselves: `FRICTION.md:95–102`. SDK-controlled construction visibility would remove misleading public items without adding a second client hierarchy.
- **Consider suppressing direct `send()` for endpoints requiring SDK target preparation.** B2 upload’s direct generated send targets its placeholder route; Registry’s three continuation operations likewise require returned Locations. These are currently private declarations, so the benefit is API correctness, not demonstrated SDK LOC deletion. Evidence: B2 F48–59; Registry F121–131.
- **Do not remove `Prepared::follow`.** It is actively used across nine domains, including maintenance improvements in Snowflake.
- **Do not remove `subdomain` because only three SDKs use it.** Those three include bucket and tenant addressing; replacing it would move host construction and validation into SDKs.
- **Do not relax `Base` to accept queries.** Base URLs and complete issued request targets are different mechanics. B2’s query-bearing upload URL demonstrates the distinction, not a reason to merge them.
- **Do not move transport construction into `concord-retry` alone.** Many of the 22 strict transports intentionally perform no SDK retries. The shared part belongs beside Concord’s reqwest boundary, if added.

**Limits and unresolved decisions**

- All savings above come from source inspection. I did not compile proposed signatures or verify API compatibility.
- A runtime-base declaration plus selective control suppression needs a small prototype before claiming wrapper deletion. Mastodon still needs advertised-host trust; Xero still needs tenant-bound references; Graph still needs authorization/query context.
- `Prepared::follow` currently checks parsing and origin only at [`prepared.rs:61–75`]( /home/canarit/projects/Concord_SDK50_Ecosystem_Handoff/work/integration/crates/concord-core/src/prepared.rs:61). It does not itself reject same-origin user information or fragments. Several SDKs explicitly reject both. Tightening that default may be sensible, but its compatibility and diagnostic consequences are undecided; it would not eliminate early SDK validation.
- Historical friction records are not always current implementation descriptions. PokéAPI’s F7–14 predates its current `Prepared::follow` implementation. Its maintenance record explicitly says the query-rewriting experiment was reverted at M153–161. Salesforce F182 says no following route exists, while current Concord demonstrably has one; its current reconstruction remains observable and intentional.
- The worktree cannot establish provider behavior beyond its code, documents and synthetic tests. In particular, caller-supplied reqwest clients remain an opaque boundary for redirect, replay and default-header guarantees.
