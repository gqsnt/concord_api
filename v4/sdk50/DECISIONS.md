## F2 — response interpretation and streaming

| ID | Obligation / proposal | Disposition | Witnesses, counterexample, cost, reversal |
|---|---|---|---|
| F2-1 | Metadata must survive a body failure. Baseline: every policy clones `received.meta()` before decoding and pairs it with the value or the error (P0 inventory §2: ~23 sites). | **CORE_CHANGE** (additive): every error raised after a head arrived keeps that head — moved out of the native response before the body is read (no clone): `Error::head()` (borrowed), `Error::head_meta()` (owned). `Incoming::chunk`/`drain` keep it too. | `checks/core-concepts/tests/x9_metadata_terminal.rs` (decode, limit, mid-body transport, drain, Incoming chunk/drain; none before a head; no secret in Display/Debug). Independent review (Sol) found `Error::meta()` widening broke `meta().is_some() ⇒ into_response().is_ok()`; **corrected**: `meta()` keeps its contract, `head_meta()` is the widened copy. reqwest 0.13.5/tower-http 0.6.11 source read by the reviewer: decompression is configured before Concord sees the response and `bytes()`/`chunk()` never read the header map. |
| F2-2 | `Received::decode_with_meta()` / `decode_limited_with_meta()` → `(T, ResponseMeta)`. | **CORE_CHANGE** (additive). | Frankfurter policy 25 → 12 lines, Nager 6 → 3, Dropbox success path; 20 more SDKs in the adoption lane. Stream readers/`Incoming` keep their response, so their head is a copy (documented). |
| F2-3 | Bounded typed document of **any** status. Baseline: ~22 sites read `bytes_limited` then `<Json as Decode<D>>::decode_body((), bytes)`, skipping the format's head checks and `Context` (14 such call sites found by grep). | **CORE_CHANGE** (additive): `Received::document::<F, D>(limit) -> (ResponseMeta, Result<D, Error>)` runs `F::check_content_type` and `F::context` before polling, reads bounded, then `decode_body`; a `Decode` failure keeps the bytes (`Error::body_unredacted`). | `x3_any_status_document.rs`: typed document + status; empty/malformed/oversized/interrupted/wrong-media all keep the status; a media refusal and a contextual-format version refusal return on a stalled body; a non-unit `Context` format (`Versioned`) runs its head contract once. Counterexample to a JSON-only helper: `Versioned` (head-derived context). Slack HTTP-200 `ok:false`, Snowflake 200/202 and S3 XML errors keep SDK code (reasons in the adoption commit). Doc corrections from the prediction probe: a failed document's error carries a copy of the head (one clone on the failure path). |
| F2-4 | `Decode::Context` and the finite/incremental split. | **KEEP_CORE**. | Context carries real state (S3 object headers, Snowflake status, ntfy truncation, `Versioned`); removing it fails those. The stateless `type Context = (); fn context(..)` boilerplate (2 lines per format) was not judged worth a second trait. Reverse if wave format authors report it as a real obstacle. |
| F2-5 | Runtime-selected response representation (Open-Meteo JSON/CSV, ClickHouse readers, Snowflake inflation cap). | **EXPERIMENT** (continues into the waves). | Three unlike current witnesses with different pressures (P0 §2 "runtime response decoder configuration"); no candidate yet beats `-> stream` + a reader chosen at run time without moving request-derived validation. Owner: coordinator; gate: a wave SDK with runtime format choice (USGS GeoJSON/CSV, FRED XML/JSON/ZIP). |
| F2-6 | Head-only outputs through the finite path (S3 `HeadFormat`/`PutFormat`). | **KEEP_CORE** (no new lifecycle wrapper). | The finite contract deliberately requires body completion before success; no defect reproduced. |

## F3 — declarations to generated usage

| ID | Obligation / proposal | Disposition | Witnesses, counterexample, cost, reversal |
|---|---|---|---|
| F3-1 | Repeated parameter blocks (SDK20 D-A5, deferred twice). Kubernetes: the same 7 list parameters on 13 endpoints and 5 watch parameters on 6, plus a hand-written `ListOperation`/`WatchOperation` trait forwarding 108 setter methods through `macro_rules!`. Stripe account override, GitHub filters, Salesforce query declarations repeat smaller blocks. | **MACRO**: `params Name(..);` on the client (optional/initialized values only), `..Name` in an endpoint's values; values spliced at the written position (wire order kept); generated trait `Name` of the group's setters implemented by every including endpoint. | Kubernetes migration: `examples/kubernetes-sdk/src/api.rs` net −119 lines; 108 per-endpoint forwarding methods → 11 default methods written once; kubernetes-sdk 26, kubernetes-app 35, maintenance-kubernetes 6 tests unchanged. Counterexample honored: a group value never reaches an endpoint that does not include it (a scope value would reach `pod(name)`), UI `param_group_not_on_other_endpoints`. Diagnostics: required value, unknown group (near-name suggestion), group on a scope/below the client, unused group, value on endpoint and group, value in two groups, group named like a generated type. Independent review fixes: `cfg`-gated trait, raw identifiers, docs without links. Probes: docs-only prediction (Terra) 10/10; first-use (Opus) found and used it unprompted. Maintenance: adding a list parameter was 13 identical declaration edits + trait/macro forwarding; now one line. Independent edit probe (Codex `gpt-6.1-sol` xhigh, `sdk50/p1-edit-k8s`): adding streaming-list parameters to all six watch endpoints touched two central sites (the `WatchOptions` group, two `WatchOperation` default methods), no endpoint declaration or forwarding; 25 tests + 6 doctests pass. Reverse if a wave needs required group values or per-endpoint variation that groups cannot express without workarounds. |
| F3-2 | Generic SDK code cannot reach the client's send policy from `Endpoint<T>` (first-use probe; Kubernetes `send_list` forwarding; a value policy `send signer;` had to be handed to helpers). | **CORE_CHANGE + MACRO**: `concord::Sends<O>` (output as a type parameter, like `Endpoint<T>`) implemented by every endpoint of a client with a send policy; a helper bound on it sends through the policy, the policy value included; its future is `Send`. | `checks/core-concepts/tests/f3_generic_send.rs`. | F3-3 | Value getters on generated handles (SDK20 W23-8; GitLab API prefix, S3 range/token read-backs, Stripe template inspection). | **EXPERIMENT** (deferred to wave evidence). | Current witnesses read the built request back; the first-use probe wanted the starting cursor for a report.
