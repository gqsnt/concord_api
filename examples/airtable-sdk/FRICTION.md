There is no private reach-through or rebuilt HTTP execution.
4. **Missing versus null offset — provider/SDK.** `src/lib.rs:35` and `:39` use a custom deserializer so a missing offset ends traversal while a present null fails decoding; `:230` rejects an empty offset. Reproduce in `tests/protocol.rs` invalid responses. Airtable's page describes omission as exhaustion; standard `Option<String>` would also accept null as absent. The SDK makes malformed continuations explicit rather than silently claiming completion.
5. **Long GETs — provider limitation.** `README.md:3` records the 16,000-character limit and no automatic POST switch. The provider's POST alternative has a distinct request contract, and is deliberately outside this GET slice. The SDK does not preflight the complete URL length; Airtable's rejection remains a provider HTTP error.
6. **Dynamic field names — provider/application.** `src/lib.rs:16` retains arbitrary JSON in a map and does not synthesize omitted empty values. `tests/workflows.rs` checks a renamed field, an unknown nested value and a missing old name. Applications must decide what a missing or renamed field means; decoding into a fixed struct would lose this behavior.
