- **Bounded success decoding.** Ordinary generated `send()` decodes without a size bound. We wrote the generic `Bounded` send policy, using `prepare`, `receive`, and `decode_limited` to impose 4 MiB. The limit is SDK policy; generic byte enforcement already exists. Smallest shared improvement: an opt-in declared per-client/endpoint finite response limit used by generated `send()`.
- **Redacted SDK errors.** Concord safely formats errors, but its native response/source accessors intentionally expose unredacted information. To guarantee this SDK's entire error surface excludes the query key and echoed error content, the policy manually copies only kind and status and discards the error. Provider classification remains SDK-owned. A generic redacted error projection retaining stage and status without a native response would remove this repeated wrapper while preserving Concord's escape hatches.
- **Pagination and provider links.** NASA's basic browse documentation does not describe response traversal and returned links may contain credentials. We expose one page plus counters and request the next page explicitly; link trust, provider pagination rules, and any traversal budget remain SDK policy. A shared primitive is unnecessary for these single-page workflows; an official, schema-backed provider continuation contract would be needed before an adapter could safely automate traversal.
- **Provider response projection.** We authored feed/browse/object serde models because Concord does not define NASA's schema; this is provider-owned work, not a shared-core defect. The SDK ignores links and unmodeled fields to avoid accidental key disclosure. No shared change needed.
