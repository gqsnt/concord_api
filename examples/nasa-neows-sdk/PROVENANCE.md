Read as the live static asset [api.nasa.gov/assets/html/authentication.html](https://api.nasa.gov/assets/html/authentication.html) and as its source [nasa/api-docs `gh-pages` `assets/html/authentication.html`](https://github.com/nasa/api-docs/blob/gh-pages/assets/html/authentication.html) (last changed by commit `fb2efa94305a9e1f39454d84ad44d19cc85bf4fe`, 2019-11-05); both copies are byte-identical (SHA-256 `3ec2f3e5f7b268d0323e08faf0f8c9b85ec88a4932c777df4e80eb215aedfe04`). The direct text fetch of `https://api.nasa.gov/` returned only the signup shell. No NeoWs endpoint was requested.

Documented facts used: `X-RateLimit-Limit` and `X-RateLimit-Remaining` are returned "on every API response"; the example `X-RateLimit-Remaining: 998` after two requests against 1,000; the default hourly limit of 1,000 requests, "Rate limits may vary by service"; limits apply per key across all api.nasa.gov requests; exceeding them blocks the key temporarily, lifted by waiting an hour; counters reset on a rolling basis; `DEMO_KEY` limits are 30 requests per IP address per hour and 50 per IP address per day.

Not documented there, so not asserted by the SDK or its tests: the HTTP status and body of a key or quota refusal (tests use synthetic 403 and 429), that a refusal carries the headers (inferred from "every API response"; the SDK reports `Absent` otherwise), what the headers report for `DEMO_KEY`'s per-IP limits, any reset or retry header, and the exact value syntax beyond the decimal example (the SDK accepts only a single field of ASCII digits).

All quota header values in `tests/rate_limit.rs` and `tests/quota_workflows.rs` are **authored synthetic**, set inline on loopback replies; no fixture file was added.
