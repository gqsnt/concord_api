# SDK07 author observations

Baseline: Concord `e04236ca`, Rust 1.99.1 / edition 2024. Changes are confined to this SDK,
the workspace member, and its lockfile package entry. No library, script, check, or other
example was edited. No live provider calls or credentials were used.

1. **Bearer auth and exact query encoding worked in the declaration.**
   Cause: Concord (positive). `src/wire.rs:31` declares both GET methods, shared bearer auth,
   JSON handling, optional query values, and a sensitive cursor. Reproduce with
   `tests/protocol.rs:16`: the returned `opaque=+/&?%2F# space` becomes
   `opaque%3D%2B%2F%26%3F%252F%23+space` on the next wire request, and decoding the wire query
   once recovers the original value. There is no URL joiner or percent-encoder in the SDK.
   `tests/protocol.rs:480` also verifies a newline-bearing synthetic token fails before I/O
   without appearing in diagnostics. The existing GitHub declaration was reading material.

2. **Slack's HTTP-200 failures require a domain wrapper around the generated output.**
   Cause: provider semantics and SDK responsibility. `src/wire.rs:9` models a required boolean
   `ok` plus optional payloads; `src/lib.rs:249` checks it before exposing a domain result.
   The generated declaration is private so its transport-level `send()` cannot be mistaken for
   a Slack-aware success. `src/lib.rs:150` and `src/lib.rs:210` reject absent success payloads.
   Reproduce with `tests/protocol.rs:237` and `tests/workflows.rs:229`: a missing payload is an
   envelope error, and HTTP 200 / `channel_not_found` is a typed provider error. Unknown error
   codes remain inspectable. This is explicit adapter code, not a patched Concord status check.

3. **The response boundary avoided rebuilding execution, but metadata retention is still
   authored once in the SDK.**
   Cause: Concord public API (positive), SDK metadata policy (adapter cost).
   `src/lib.rs:223` uses `Endpoint::prepare()?.receive().await?`, copies headers/status/operation,
   then consumes the declared decoder or the bounded error body. `src/lib.rs:245` attaches
   the captured head to a decoding failure. The original operation comes from Concord; no
   fabricated operation label or status is used. Reproduce with `tests/protocol.rs:268` and
   `tests/protocol.rs:417`: JSON/content-type/transport/limit errors keep the response head and
   operation, and a broken 429 body does not replace the rate-limit error. The PokéAPI metadata
   adapter supplied the general read-head-before-decode pattern; this helper was written for
   Slack's different status/body semantics. There is no `send_raw`, `into_parts`, private
   reach-through, native execute, or vendor execution escape in this SDK.

4. **The ordinary pagination facade preserved completion, with one provider projection.**
   Cause: Concord pagination (positive); provider/SDK envelope adaptation.
   `src/lib.rs:168` owns cloned client/options and projects members, body cursor, and page
   metadata into `Page`. `src/models.rs:27` treats only the empty string as an absent non-null
   cursor; no trim or decode occurs. The cursor is cloned because both page metadata and the
   traversal retain it. `tests/workflows.rs:32` follows a short page and then an empty page;
   `tests/workflows.rs:127` keeps a bounded prefix; `tests/workflows.rs:149` keeps a failed-page
   prefix; `tests/workflows.rs:186` proves the item stream emits a typed terminal error.
   No scheduler, report reconstruction, or custom `Stream` implementation was needed. The
   caller must still respect Slack's short cursor lifetime and unchanged listing options;
   the SDK does not persist or timestamp cursors.

5. **Finite success decoding has no bounded typed consumer in the inspected public boundary.**
   Cause: Concord API limitation; accepted SDK limitation for this scope.
   The generated `Received` rustdoc exposes `decode()` and `bytes_limited()`. The latter says
   it bypasses declared handling. `src/lib.rs:231` uses it for non-2xx bodies, bounded to
   64 KiB, while `src/lib.rs:245` keeps declared JSON/content-type behavior for successes.
   Thus successful pages are buffered without an SDK byte limit. Reproduction: inspect those
   two calls and the `Received::decode` / `Received::bytes_limited` rustdoc generated by the
   documented cargo-doc command. This was a public API inspection, not a failed runtime test.
   No custom success-body reader was rebuilt to add a limit. README states this limit and that
   item streaming works between buffered pages rather than incrementally parsing JSON.

6. **The custom-format guide contains older native-route advice.**
   Cause: docs. `docs/CUSTOM_FORMATS.md:51` discusses runtime media metadata through native
   construction, and `docs/CUSTOM_FORMATS.md:57` directs incremental reads to `send_raw`.
   Reading the generated rustdoc and current recipes exposed `Received` and the incremental
   public boundary. This Slack slice needs finite JSON, so `src/lib.rs:223` uses `receive`
   and never needed those older native routes. The frozen documentation was left unchanged.

7. **Harness assumptions caused two compile/assertion corrections.**
   Cause: SDK tests, not Concord correctness.
   The first workflow compilation tried `futures_util::poll!` while the workspace disables
   that macro's feature. Replaced it with `std::future::poll_fn` and `Future::poll`, without
   adding a dependency or feature (`tests/workflows.rs:268`). The first complete protocol run
   had 12 passes and 4 failures because expected operation display strings omitted `GET`;
   `Operation::Display` includes the method. Corrected only expected strings in
   `tests/protocol.rs:268` and the other operation-identity assertions. The implementation did
   not change for those failures. An initial unused-import warning was also removed.

8. **Verification and dependency results.**
   Cause: workspace integration. The first locked test refused the new package's missing
   lock entry. One offline unlocked test registered it; subsequent required commands used
   `--locked`. The build cache briefly reported a file-lock wait; it was allowed to finish.
   Commands all used `CARGO_BUILD_JOBS=5` and the user-specified shared `CARGO_TARGET_DIR`.
   Observed passing gate: 16 protocol tests, 9 workflow tests, 4 doctests; zero unit tests.
   `cargo clippy --locked -p concord-sdk-slack --all-targets -- -D warnings` and
   `cargo fmt -p concord-sdk-slack` passed. The 429 workflow advances virtual time through
   29 seconds and then 1 second and observes no second request until the caller explicitly
   makes it (`tests/workflows.rs:268`). Fixture sources and synthetic mutations are in
   `PROVENANCE.md`. Dependencies reuse already locked versions; the lockfile adds only this
   package. No generic protocol dependency was necessary beyond serde JSON and the Concord
   traversal/format APIs.
