# First-use consumer trace

## Predictions before implementation

### A — query and retrieve
A filtered query should POST `/v1/data_sources/{id}/query` with JSON `filter` and `page_size`, bearer and Notion-Version headers. A further POST should preserve the filter and add the previous `next_cursor` as `start_cursor`. `query_pages(...).items().collect_complete()` should return ordered query results only after a validated final page; `as_page()` selects a page and `retrieve_page` should GET `/v1/pages/{id}`, returning its decoded properties and response metadata. A later failed page should return `Incomplete` with the previously collected prefix and an error; a Notion error document should surface as `Error::Provider` with its code and metadata.

### B — children and rendering
`children(parent, size).items().collect_complete()` should GET `/v1/blocks/{parent}/children` with `page_size`, then pass each `next_cursor` as a `start_cursor` query parameter. It should return blocks in order only after the final page, and `render::block` should render the selected supported rich text. A failed later page should retain the prefix as an incomplete result; a budget-limited traversal should report that it ended early, not claim completion.
