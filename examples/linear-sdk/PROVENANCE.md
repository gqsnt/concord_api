# Provenance

Sources rechecked 2026-11-06. Linear's pages do not display a version or publication date; the pinned reference is the unversioned page content accessed on that date, not a pinned server schema. No example response bytes were downloaded from Linear. All fixtures are hand-authored synthetic UTF-8 JSON with a final LF, with invented IDs, text, cursors, diagnostics, and extension values. They are examples of shapes, not vendor conformance evidence.

The SDK's fixed named documents and variable declarations adapt the documented inline queries to variables; exact request bytes are asserted in the tests. The synthetic body shapes and tests do not validate the currently deployed schema or actual server behavior.

**`dueDate` maintenance (2026-11-06).** The docs pages above do not list `Issue` fields with nullability. The field and its nullability come from the `type Issue` declaration `dueDate: TimelessDate` (no `!`; "The date at which the issue is due.") in Linear's public SDK repository schema, <https://github.com/linear/linear/blob/master/packages/sdk/src/schema.graphql>, read on 2026-11-06 through a summarizing fetch tool rather than by inspecting the raw bytes; it is unversioned and not a pinned server schema. The `TimelessDate` serialization was not checked: the date-shaped values are synthetic and the SDK does not parse them. Every existing fixture that contains an issue object (the six `first-use-*` issue and page fixtures as well as `page-one`, `page-partial`, `issue` and `issue-partial`) gained a `dueDate` member after `description`, because a response to the new selection must contain it; no other byte changed. The locations in the two new fixtures were computed from the SDK's sent documents (column 114 in the list query, 67 in the lookup) and the tests assert that they point at `dueDate`; Linear's own reported locations were not observed.
