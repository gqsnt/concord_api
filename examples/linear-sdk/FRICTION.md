# Concord authoring notes

Ordered observations; file:line references reproduce the final implementation or tests. The Shopify SDK supplied the fixed GraphQL body/envelope and connection-adapter pattern; the OpenAI SDK supplied the `Received` response-head/error-body pattern. Both are normal workspace examples, not vendor SDKs.

1. **Easy — Concord.** `src/lib.rs:47` declares the endpoint, shared authorization header, JSON response and two typed POSTs. `tests/protocol.rs:50` verifies the generated method, path and headers, and the two bodies. The `#[sensitive]` client parameter keeps the authorization value out of the generated client's debug output.
2. **GraphQL request framing — SDK / provider protocol.** `src/lib.rs:14` and `src/lib.rs:17` handwrite the two operation names/documents, variable wrappers, and an `Encode` implementation, then `src/lib.rs:291` and `src/lib.rs:311` pair each document and name again at the call site. `tests/protocol.rs:58` and `:86` reproduce the exact JSON. Concord's generic custom-format boundary works, but there is no built-in binding of a document, operation name, variables and result type; maintaining that pairing is SDK work.
3. **Response and error handling — Concord / SDK.** `src/lib.rs:219` explicitly prepares and receives every call, copies the response head, branches on HTTP status, reads and parses an error body, bounds successful decode and wraps errors. Concord exposes the pieces publicly and avoids a second execution, but preserving typed provider errors and HTTP metadata requires this adapter. `tests/protocol.rs:90` reproduces both non-2xx and 200 errors-only responses. A decode failure keeps metadata and Concord's error, but not the consumed malformed body or independently parsed GraphQL diagnostics.
4. **Connection adapter and caller policy — Concord / application.** `src/lib.rs:324` validates pageInfo, keeps the entire response on a malformed page, projects items and passes diagnostics in page metadata; `src/lib.rs:370` adapts a cloned client to `Pages`. `tests/workflows.rs:24` reproduces a partial second page and `tests/workflows.rs:77` a bounded traversal. Concord pagination handles completion and resume, but the SDK must implement the connection projection and application must inspect every page: flattening to items discards page metadata, including GraphQL errors. A non-adjacent cursor cycle is not detected by this adapter, so callers should bound traversal.
5. **Nullable field validation — SDK / serde.** `src/lib.rs:61` supplies a deserializer because a plain `Option` also accepts an omitted selected field. `tests/protocol.rs:121` supplies a response missing `description`: it is refused, whereas the synthetic null field with a GraphQL diagnostic is retained in `tests/protocol.rs:26`.
6. **Selection and model agreement — SDK / GraphQL (maintenance, `dueDate`).** The selected field set is written three times with no compile-time link: the `LIST` and `ISSUE` documents (`src/lib.rs:14`, `:15`) and the `Issue` model (`src/lib.rs:72`). Dropping `dueDate` from `LIST` alone still compiles and still decodes every fixture (they contain the key); only request-side assertions fail: the exact body (`tests/protocol.rs:86`), the first-use `wire` helper, and the location check in `tests/workflows.rs:125`. Not Concord-forced: Concord is not a GraphQL client and the SDK chose string documents. See `MAINTENANCE.md`.
