# concord-sdk-strava

SDK37 covers an authorized athlete's activity pages, activity detail and edits of an
owned activity, plus a one-shot activity-file upload followed by bounded processing polls. The hierarchy
is generated by `concord::api!`: `Strava → athlete/activities/uploads → endpoint`.
Both connected workflows run against `examples/testserver`; live provider calls:
**NOT_RUN**. The package is example-assisted through required guide excerpts; no existing
`*-sdk` source file was opened directly. Sources, fixture origins and limits are in `PROVENANCE.md`;
Concord costs are in `FRICTION.md`.

## Calling the slice

The application handles browser consent, validates callback state and accepted
scopes, then exchanges the single-use code. Activity reads require the accepted
`activity:read` or `activity:read_all` permission; uploads and activity updates require
`activity:write`.
The examples below compile as rustdoc examples and are never executed in tests.

```no_run
use concord_sdk_strava::{Credentials, Error, OAuth, Session, TokenRequest, transport};
use std::time::Duration;

async fn connect(code_from_validated_callback: String) -> Result<Session, Error> {
    let credentials = Credentials::new(123, "application-secret".into())?;
    let oauth = OAuth::new(transport(Duration::from_secs(30))?);
    let tokens = oauth.oauth().token(TokenRequest::authorization_code(
        &credentials, code_from_validated_callback,
    )?).send().await?.value;
    // Check accepted scopes from the callback and token document before continuing.
    Session::connect("https://www.strava.com", "https://www.strava.com",
        credentials, tokens, Duration::from_secs(30))
}
```

Retain the `Session` for `latest_tokens().await` and persist its latest refresh token
after calls, including failed API calls that may have refreshed first. Cloned
clients share that session. Sessions represent a single athlete; storage and
coordination across processes belong to the application. Separate sessions do not
share the application's provider-wide quota observations.

```no_run
use concord_sdk_strava::{Session, pagination::Resume};
use std::num::NonZeroUsize;

async fn activity_workflow(session: &Session)
    -> Result<(), Box<dyn std::error::Error + Send + Sync>>
{
    let api = session.client();
    let mut pages = api.athlete().pages(100, Resume::Start,
        NonZeroUsize::new(10).unwrap())?;
    let mut first_id = None;
    while let Some(page) = pages.next_page().await? {
        if first_id.is_none() { first_id = page.items.first().map(|a| a.id); }
        // Consume page.items and inspect page.meta.rates here.
    }
    if let Some(id) = first_id {
        let activity = api.activities().get(id).send().await?.value;
        assert_eq!(activity.id, id);
    }
    Ok(())
}
```

An update sends only the fields set on `ActivityUpdate` and returns the updated
activity. `clear_gear()` sends Strava's `gear_id` value `none`; `commute(..)` is sent as the
`Commute` tag, never with the legacy top-level `commute` field; the deprecated `type` is
never sent. When the session's stored `Tokens.scope` is known and lacks `activity:write`,
the update is refused with `Error::MissingScope("activity:write")` before any refresh,
admission or dispatch. With unknown scopes (`None`) it is sent and the provider decides.
Updating an Only Me activity also needs `activity:read_all`; the provider enforces that.

```no_run
use concord_sdk_strava::{ActivityUpdate, Error, Strava};

async fn rename(api: &Strava, id: u64) -> Result<(), Error> {
    let edit = ActivityUpdate::new().name("Gravel loop".into()).commute(true);
    match api.activities().update(id, edit.clone()).send().await {
        Ok(updated) => assert!(edit.is_reflected_in(&updated.value)),
        // The update may have been applied: re-read before deciding to send it again.
        Err(e) if e.is_ambiguous() => {
            let current = api.activities().get(id).send().await?.value;
            if !edit.is_reflected_in(&current) { /* the application decides */ }
        }
        Err(e) => return Err(e),
    }
    Ok(())
}
```

An update is never resent by the SDK: a timeout, a lost connection or a 5xx is uncertain
(`is_ambiguous()`), because the edit may have been applied. It is charged to the same
overall and non-upload windows as reads.

`pages` requires a nonzero page cap, accepts page sizes 1–200 and continues until an
empty page, including after a short page. A cap is `PagesError::Bounded` with a resume
position; a provider failure retains its failed page and collected prefix through
`collect_complete`. Resuming requires the same athlete, filters and page size.
Changing data between numbered pages can cause gaps or duplicates. The generated
single-page endpoint also exposes `before`, `after`, `page` and `per_page` setters;
it is the low-level path and leaves numeric validation to the provider.

```no_run
use concord_sdk_strava::{DataType, Error, PollPolicy, Session, UploadFile, concord::reqwest};
use std::{num::NonZeroUsize, time::Duration};

async fn upload_workflow(session: &Session, open_file_body: reqwest::Body)
    -> Result<u64, Error>
{
    let file = UploadFile::new("ride.gpx", DataType::Gpx, open_file_body)?
        .external_id("my-source-record".into());
    let result = session.client().uploads().upload_and_poll(file, PollPolicy {
        max_polls: NonZeroUsize::new(20).unwrap(),
        interval: Duration::from_secs(1),
    }).await?;
    Ok(result.activity_id.expect("completed processing has an activity ID"))
}
```

Pass a `reqwest::Body::wrap_stream` over an already opened file/byte source for
one-shot input. Preparing the request does not poll it. `UploadFile` is not
`Clone`, and its prepared native body cannot be cloned. FIT, TCX, GPX, their gzip
variants and limited strength JSON are selectable; the SDK does not validate the
file format. Optional name, sport override and external ID are supported. An
external ID is a label, with no assumed idempotency guarantee.

To retain a receipt before polling, use `api.uploads().create(file).send().await`,
then `api.uploads().poll(receipt.value, policy).await`. `PollBounded` retains the last
receipt for resumption. Polling waits at least one second before every status GET;
a transient status retry also waits at least one second. A returned `activity_id`
means complete; a non-null `error` means processing failed. English status text is
not parsed. Error text may include HTML and must be treated as untrusted data.

## Failures and execution policy

| Outcome | SDK behavior |
|---|---|
| Invalid filename, configuration, poll interval or page adapter input | `Error::Invalid`, before sending the affected request |
| Preparation refusal | `Error::Concord` / Concord `Build`, no dispatch |
| Read transport failure without a head, or HTTP 502–504 | At most two application attempts; 25 ms backoff (one second for status polls); never for an update |
| HTTP 401 | Return it without replay; invalidate that credential generation so a later call refreshes |
| Expired token | Single-flight refresh before dispatch, retaining the newest refresh token |
| Token acquisition failure | `Error::Auth`; no application dispatch; no automatic token-grant replay |
| Upload timeout / body-source failure with no head | `Error::Ambiguous`; the upload may have been accepted; no replay and no polling without a receipt ID |
| Upload 5xx or unreadable successful receipt | Ambiguous; never automatically re-upload |
| Update with stored scopes lacking `activity:write` | `Error::MissingScope("activity:write")`; no refresh, admission or dispatch |
| Update timeout, connection loss, 5xx or unreadable 2xx | Ambiguous (`is_ambiguous()`); one attempt only; re-read the activity |
| HTTP rejection, including 400, 401, 403, 404, 409, 422 and 429 | `Error::Http`; status remains available even when its document is unreadable |
| Malformed, interrupted, too large or wrongly labelled success body | Concord `Decode`, `Transport`, `Limit` or `Metadata`; no body-driven retry |
| Upload processing error / exhausted poll count | `Processing` / `PollBounded`, with the upload status retained |

Finite success bodies are limited to 1 MiB (OAuth: 16 KiB); error documents to
16 KiB. `HttpFailure.document` independently reports JSON/media/read/limit errors.
Provider strings and credentials are withheld in SDK error, token, upload and
response `Debug`/`Display`; explicit fields and Concord's `*_unredacted` accessors
remain deliberate disclosure paths. Activity model `Debug` displays activity data.

`RateLimits` keeps overall and non-upload quota pairs independently, each with a
short and daily counter. Missing, partial, repeated and malformed pairs are
observable. Admission atomically checks the applicable window keys: the two overall
keys for uploads, all four for every other request (reads, status polls and updates),
as the rate-limits page exempts only uploads from the non-upload limit.
Windows reset at natural quarter-hours and midnight UTC using the local wall
clock. HTTP 429 is returned immediately with all available counters: it never
triggers a retry that could consume more daily quota. Exhausted windows gate
subsequent calls locally. A valid `Retry-After` adds a minimum global cooldown; an
unexplained 429 without a valid hint conservatively gates until the next UTC day.
Observations are process-local estimates, not a reservation of distributed quota.

Use `Session::connect`, `session.client()` or `Strava::connect`: their transport
disables redirects, referer propagation and reqwest retries and uses the supplied
finite timeout. The low-level generated `new(http, config)` can accept an arbitrary
transport, so callers using it must preserve those settings. The application retry
count excludes OAuth requests. Total duration is bounded by per-request timeouts,
at most two read attempts, page/poll caps and poll delays, rather than a single
workflow-wide deadline.

Generated `prepare()` remains an unauthenticated request: authentication is applied
by the send policy immediately before dispatch. `Prepared::send()` bypasses the
SDK policy, including refresh, admission, typed errors and retries. Ordinary
callers should use generated endpoint `send()`.

Excluded: routes, segment competitions, webhook hosting, automatic re-upload,
automatic resending of updates, the update fields `hide_from_home`, `type` and tags other
than `Commute`, browser hosting, durable credential storage, distributed quota
coordination, full activity models and file-content validation.

## Verification

Run from the workspace root, one cargo command at a time with
`CARGO_BUILD_JOBS=4` and the default worktree `target/`:

```text
cargo test --locked -p concord-sdk-strava
cargo clippy --locked -p concord-sdk-strava --all-targets -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --locked -p concord-sdk-strava --no-deps
```
