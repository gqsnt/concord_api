1. Search and metadata: construct `Fred` with `http_client()` and `FredConfig`, set a loopback base URL, call `search("industrial production")` with a small `SearchLimit`, then select a returned `id` and call `series(id).metadata().send()`. Search sends GET `/fred/series/search` with `api_key`, `search_text`, `limit`, and `offset` in the query, no request body, and an XML Accept header; metadata sends GET `/fred/series` with `api_key` and `series_id`, no body, and XML Accept. Exact Accept spelling is not obvious from the public rustdoc. XML is default and no `file_type` is needed. Search returns a `SearchPage` with count/offset/limit and `seriess`, metadata returns a `Metadata` containing a series array. For more than one page use `pages` and keep pages already received; `next_page()` returns `None` at completion and errors include the failed offset or bounded resume point. Invalid limit fails locally, non-2xx yields `Error::Http` even with a broken provider error document, and bad media or malformed XML yields Concord metadata/decode errors. The key appears on the wire as a query value but should be redacted from formatted handles and errors.

2. Observations and export: call `series(id).observations()` for XML and `observations_json()` for JSON, with limit/offset as needed, then `export_csv()`. All send GET `/fred/series/observations` with `api_key`, `series_id`, `limit`, and `offset`; JSON adds `file_type=json`, CSV adds `file_type=csv`, XML omits it. They have no body and use an appropriate Accept header (exact values uncertain). Observations return an envelope with metadata and string values, including `.` and `NA`; pagination ends with `None`, preserves earlier caller-owned pages on a later failure, and exposes a resume offset on a bound. CSV returns `CsvExport`, whose `csv()` is the extracted member bytes and optional `readme()` is separate. The response must be ZIP, not a plain CSV body: `text/csv` fails metadata, CSV bytes disguised as ZIP fail decode, and over 8 entries or 4 MiB extracted fails decode (over 1 MiB compressed HTTP body fails limit). HTTP errors remain HTTP errors; malformed XML/JSON/ZIP fail decode. Invalid limits fail before a request; secrets follow the same rules as search.

## Friction, in order

1. Generated rustdoc is HTML. An attempted local extraction with Python BeautifulSoup failed (`ModuleNotFoundError: No module named 'bs4'`); the standard library HTML parser sufficed. No dependency was added.
2. The search result field is `seriess`, an unusual spelling, but both the README and rustdoc explain it. The series fixture needs numerous metadata fields; the public `Series` rustdoc lists them.
3. The first test crate triggered the workspace `missing_docs` warning; a crate-level description removed it.
4. The README's pagination example is usable, but interpreting the stop and recovering a partial traversal required the separately generated public `concord-pagination` rustdoc: `Page` exposes `items`/`next` and unit metadata, while `PagesError::resume()` exposes the position. No extra trait import was needed. The ordinary generated `send()` needed no extra trait import either.
5. I initially used `http.meta.status` as a field. Rust reported it is private and suggested `status()`; that accessor compiled. `HttpError` rustdoc mentions status in metadata but does not show the accessor inline. A link to `ResponseMeta::status()` from that documentation would make this easier to find.
6. The endpoint rustdoc says the codec may set `Accept`, but does not show its concrete value. I initially asserted `application/xml, text/xml`; both tests failed with actual `text/xml`. JSON was `application/json` and CSV was `application/zip`. Explicit generated endpoint documentation of the actual Accept value would help wire-level callers; this is a proposed shared generated-documentation improvement, not an edit to a shared crate.

No SDK source, pre-existing SDK tests, `FRICTION.md`, or `PROVENANCE.md` was consulted. The SDK manifest and public rustdoc for `concord-example-testserver` and `concord-pagination` were consulted for fixture setup and pagination. No new dependency or lockfile change was needed.

No mismatch was observed beyond the initially uncertain XML header.
