  concord.contract/3 records the full per-endpoint effective contract of section 18.2)

With CARGO_INCREMENTAL=0 every source edit recompiles the whole fixture crate, so "build", "edit", "parent edit"
and "cold" all measure one whole-crate compile and agree within run-to-run noise. The repeated 100-endpoint rows
give that noise: v3 build 2534-2628 ms (2365 in the default run), edit 2499-2568, parent edit 2451-2568, cold
2467-2596 (the first repeated row's expand of 763 ms is an outlier against 414-427); v2.1 build 2019-2093 (2073),
edit 2004-2023, parent edit 1984-2000, cold 2001-2045. That is up to about +/-5% between runs of one point.

With CARGO_INCREMENTAL=1 the local edit (one endpoint's route) still costs about a whole rebuild in both dialects
(1000 endpoints: v3 31609 ms, v2.1 23430 ms), while the parent edit (root timeout) is much cheaper in both (v3
11126 ms, v2.1 12960 ms; v3 -14.2%). Why the one-route edit invalidates almost every incremental unit in both
dialects was not investigated. Incremental full builds are slower than non-incremental ones (v3 1000-endpoint
build 31685 vs 23137 ms; v2.1 22276 vs 18078 ms).

Growth over the five fixture sizes (default runs): expanded lines are exactly affine in the endpoint count (v3
345.5 lines per endpoint from 1 to 100 and from 1 to 1000; v2.1 332.0). Compile time is not strictly linear: the
marginal build cost per endpoint over 1->100 / 100->500 / 500->1000 is 19.57 / 22.09 / 23.88 ms for v3 and
16.36 / 17.72 / 17.83 ms for v2.1 (edit, parent edit and cold show the same pattern: v3 500->1000 is 1.08-1.11x
its 100->500 slope, v2.1 0.98-1.05x). Each size is a single run apart from the repeated 100-endpoint rows, whose
spread (+/-5%) is as large as these curvature differences, so the data do not resolve whether v3's compile time
grows more super-linearly than v2.1's. Over the whole range the marginal build cost is 22.73 ms per endpoint (v3)
versus 17.64 ms (v2.1).

Attribution: the compile-time and size growth is generated code for newly required functionality (typed owner
projections and value readers per owner and endpoint (section 16.3), per-endpoint request/intent/view types, the
value-control matrix (section 4.3), the full static contract description (section 18.2) and the contract export).
The compile-time delta was not broken down per generated item in this slice. The steady request-head attribution
is in ATTRIBUTION.md.
