# What can change between releases

*[Concord](../../README.md) · [docs](../README.md) · guide*

Use this page to decide when to upgrade Concord and how to write code that can follow the next release. The version rules for patches, minor releases and major releases apply to stable versions.

## Patch, minor and major releases

- **Patch releases are for fixes only.** The contracts describe the behaviour a fix restores. [The contracts](../reference/contracts.md)
- **Minor releases can add to the library and the language.** A new method on a generated call, handle or client must start with `with_` (C1.6). A minor release can also raise the minimum Rust version. [Reserved names](../reference/contracts.md#c1-the-description) and [scope and limits](../design/scope.md#what-can-change-without-breaking)
- **Breaking changes belong in a major release.** This includes changing an existing library signature or a signature generated by `api!`, removing a Cargo feature, changing which features are on by default, and changing the major version of a dependency whose types or errors you can reach through Concord. [Generated code](../reference/contracts.md#c10-the-generated-code-and-the-log), [features](../reference/crates.md#the-features-of-concord-api) and [public dependencies](../reference/crates.md#what-the-public-surface-is-tied-to)

## Messages, generated code and your own methods

- **Run-time error vocabulary is fixed.** C6.2 defines what `Display` and `Debug` print, down to the words for a kind, class or note. A minor release can revise the wording of the 46 macro diagnostics and the prose that Concord generates for rustdoc while keeping the underlying rules and the information promised by C10.4. The compiler tests compare the current macro messages word for word, and tests also check selected generated text. [Run-time errors](../reference/contracts.md#c6-the-error), [compile-time messages](../reference/messages.md#1-at-compile-time) and [generated documentation](../reference/contracts.md#c10-the-generated-code-and-the-log)
- **Use documented entry points.** Concord can change `concord::__private` and other hidden implementation items in any release. You can call an option setter declared by your description even when rustdoc shows it on the endpoint's type instead of on the call. Rust's own diagnostic wording follows your compiler. [The hidden interface](../internals/engine.md#the-hidden-interface-method-by-method), [generated documentation](../internals/macro.md#the-generated-documentation) and [compiler messages](../reference/messages.md#1-at-compile-time)
- **Keep `with_` for Concord.** When you add a method to a generated type in your own `impl` block or extension trait, choose a name that starts differently. A new inherent method can clash with yours or take precedence over a trait method. [Reserved names](../reference/contracts.md#c1-the-description) and [the public API of a client](calling.md#the-public-api-of-a-client)

## Before you upgrade

- **A minor release can mark an API deprecated.** Removing a deprecated public API takes a major release. If you mark a node in your own description, Concord carries the attribute to the corresponding generated items. [What can change without breaking](../design/scope.md#what-can-change-without-breaking)
- **Release candidates can break compatibility.** Pin the Git revision if you want to choose when to take the next candidate. Read the changes before updating. [Changelog](../../CHANGELOG.md)
- **Read the changelog for breaking changes.** A fix for security or soundness that breaks compatibility needs a release decision under the version rules above. [Changelog](../../CHANGELOG.md) and [what Concord promises](promises.md)
- **Concord requires Rust 1.96 or later.** The release checks run on x86-64 Linux. They check the feature combinations in the release matrix on stable and 1.96. They also test the macro on 1.96, with four groups of compiler diagnostics compared word for word on stable. [Requirements](../../README.md#requirements) and [release checks](../../CONTRIBUTING.md#the-slower-checks)
