# The cases: every case that the rules must decide

*Concord V5 design · reference · [index](../README.md) · the other sheets: [grammar](grammar.md), [rules](rules.md), [messages](messages.md), [contracts](contracts.md) · how: [the engine](engine.md), [the macro](macro.md)*

A design has no hole when every case has one outcome. This page holds every case that the rules must decide, in nine tables, each case with its one outcome and the place where it is said. Nothing here is new: a cell only repeats one of the six pages above. Where they are silent, or say two things, the cell says so.

Three marks:

- **NOT SAID**: the six pages do not give the outcome, or do not give a piece that the cell needs (which message, when). The cell says what is missing. Nothing was guessed.
- **SAID TWICE**: two places give the case two outcomes. The cell names both.
- "Does not arise" and "cannot be": another cell already refuses the case.

How a place is written: `rule 13` is a row of the rules; `sentence 5` is one of the nineteen sentences of the grammar; `C5.2` is a contract; `message 32` is a message at compile time; `messages 2` is the table of run time texts; `engine 3.2` and `macro 4` are sections.

The count of cells and the list of every marked cell are at the end.

## 4. A value and its place

A value is written by `serde` in three shapes: nothing, one text, several (C2.4). A type with no `Serialize` does not compile (macro 7); a shape that the place does not take is a Build error (C2.4; rule 8). The macro does not look at the type of an input (macro 1): only the mark `?` is seen at compile time.

The last two columns are an entry of a body of entries. There the value is a template, anything that `serde` can write, or a `Secret` (grammar, "What stands on the right"), and the function before the block gets all the entries as one map (sentence 18; C2.14): `json` writes it with `serde_json`, `form` with `serde_urlencoded` (C2.9). A `None` writes nothing there, as in `query` and in `headers`: one level of `Option` is presence, and what is inside is written as the format writes it (rule 8; rule 9; C2.14). The macro knows no type for this: `Entries` asks `serde` whether the value is a `None` (C2.14; engine 2.1). A form has no `null`: there an inner `None` writes no pair either, and a list or a struct as a value is a Build error (rule 9; C2.14). The unit (`()`) is not a `None`: in a body it is written as the format writes it, `null` in JSON, and a form cannot write it, which is a Build error; in a query and a header it writes nothing (C2.4; C2.14).

## 6. Another try

Three things must hold for another try: the request can be copied; it may be repeated, by its method, by its mark, or by a status that the policy lists with `not_applied_on`; and the failure is worth it (C4.1; rule 18). The method is the one of the request as it was built, before any middleware (C4.1). The expression of the mark runs once for a send, after `idle_timeout` and before the request is built (rule 10; C4.1; C10.3). The order of the checks is engine 3.2. "Another try" below always means: if a try is left (3 in all for `Retry::standard()`, C4.2) and the wait is allowed (C4.3). When the tries run out, the last outcome is the result (C4.4). A `with_retry` on a call replaces the whole policy of the client (C4.6).

### 6.1 Retry is off

The error is the result, and `e.retry_after()` gives the longer of two waits: the `Retry-After` of the answer, and the wait that a rule of `when` asked for the try that did not happen. No rule is asked twice: the decision gives what was asked with its verdict (rule 18; C4.3; C6.1; engine 3.2, step 7).
- A `Retry-After` is read as seconds or as a date. One that cannot be read counts as none, and a date in the past is a wait of zero (rule 18; C4.3).
- The random part of a wait is drawn again for each wait: two waits of one call are not tied to each other (engine 3.2).
- Sentence 2 of the grammar names two ways, the method and the mark: they are the ones that the description sets. The third is in the policy (rule 18; C4.1).

## 7. The clocks

A clock ends a wait, and nothing else: work that can finish without waiting finishes, and code that does not yield is not interrupted (C7.6). When a clock ends, the caller gets a Transport error of class timeout whose note names the clock, what it waited for, and where its length is set (C7.6; messages 2). An outcome that is already known, a refusal or the Mismatch of `no_arm`, is given in its place, with `kept()` saying interrupted (C7.6; engine 4). Two clocks that end at the same instant: the one that covers more is reported, `timeout` over the connect timeout, over a wait between two tries, over the clock for silence (engine 4).

## 8. Pages

Nothing is sent before the first `try_next()`. The request of each page is built when that page is asked for (C8.4). After a page arrives, the pager runs before the page is given; the page is always given first, and what was found about the next one comes with the following `try_next()` (C8.4). After an error the pages are over: every later `try_next()` gives `Ok(None)` (C8.4; rule 17).

"The same request" is: the same method, the same URL without its fragment, the same values of each header, in their order, and the same bytes of the body, with what a secret wrote in the URL or in a header left out: a piece of a path, a pair of the query, a value of a header (rule 17; C8.4; engine 7). A value of a header is left out by its `sensitive` flag, so one that `edit_request` marks is left out too (C3.1; C8.4). A body is compared as its bytes (rule 17; C8.4; engine 7); a body that is a stream has no bytes to compare, and a request with one is never "the same request" (C8.4; engine 7). This check and the check of the origin look at the request as it was built, after `.edit_request(…)` and before any middleware (C8.4). The request of a page is built once, by the first half of a send; the origin is checked on it first, then "the same request"; then that same request is sent (C10.10; engine 7, `Ready`).

`at_url` gives a path and a query, never an origin: a URL at another origin than the one that the call builds is a Build error, in pages and outside them (rule 17; C8.6; engine 7). It is checked when the request is built, before the edits of `edit_request`; the pages are held to the origin of their first request, as it is after those edits. The two checks are apart (engine 2, step 3; engine 7).

## 9. A secret and a change of `base`

A value "holds a `Secret`" when it is a `Secret`, an `Option<Secret>`, a reference to one, or a template with one in a hole (C2.4). An entry, or a piece of a `path`, with such a value is bound to the `base` in reach where it is written: the one of its own node, or the nearest above. Only where none is in reach (a secret on the client, above every `base`) is it bound to the first `base` below, on each branch (sentence 10; rule 16; C8.9). Under any other `base` further down, the description does not compile. Any `base` written below is another `base`, also with the same text (rule 16; C8.9). A `base` that a part holds is the `base` of the node that names the part (rule 25): in this table it is written on that node. The macro says the same rule: it wraps an inherited value in the check when a `base` was in reach at the writer and one more is written below it on the way, or when none was in reach and two are written below (macro 2, step 3, the row of an entry).

The message is `rustc`'s, in Concord's words (messages, opening; macro 7). At an entry: `a secret does not follow a change of base`, with the note `write this entry again with override, or remove it, under the new base`. At a piece of a `path`: `a secret in a path does not follow a change of base`, with the note `write this path under each base that needs it, rather than above those bases`.
